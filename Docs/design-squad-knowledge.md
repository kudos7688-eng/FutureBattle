# 知識を分隊単位にする（設計、未実装）

2026-11-23 作成。ユーザーの相談「観測ルールを厳密に守るのでなく、プレイヤーからそう感じられるという基準にすると、軽く・簡単にできる所はあるか」から。採否と着手はユーザーが決める。実装・ビルド・試合はしていない。

## 1. ねらい

- 観測ルールを「プレイヤーが見て分かる判断は観測のみ。見て分からない内部処理は簡略でよい」の2段にする。
- 兵1人ずつの記憶と兵から兵への報告を、分隊で1つの表に置き換える。
- 視線の光線のうち、分隊がもう知っている敵へ向けた分を減らす。

## 2. 今の形（2026-11-23 の main）

- 兵ごとに接触の表（`FBattleObserver::Contacts`）と発見の途中の時刻（`DetectionStarted`）を持つ。0.2秒ごと（敵が見えていない兵は0.4秒ごと）に、範囲内の敵すべてへ視線の光線を出す。発見には0.6秒かかる。
- 見えている接触は、16m以内の味方の兵1人ずつへ0.8秒遅れで届く（`PendingReports`。送り手・受け手・敵の組ごとに1件）。待ちは最大1万件を超え、保存にも入る。
- 分隊の判断はすでに分隊単位で読んでいる。`UBattleLeaderRuntime::Think` は「隊員を順に回って接触を探す」形を約20か所で繰り返し、`UBattleSquadTactics::Observe` は隊員の接触を1つの表にまとめ直している。
- 兵ごとの接触を本当に使うのは次の所：
  - 射撃の条件（自分で見えている接触＋発射直前の視線判定 `CanSee`）
  - 撃ち返し `-BattleOwnTarget`、見張りの向き、歩いている兵の視線
  - 撃たれた時の反応（`-BattleHitReveal` など）
  - プレイヤー側の表示（自軍の誰かに見えている敵だけ出す）

負荷（11-23 10時25分の STATUS）：認識は1フレーム 1.2〜1.4ms。うち視線の走査が 1.1〜1.2ms、報告は 0.09〜0.16ms。マップIで光線は1試合2383万本。光線のうち分隊が既に知っている敵の分は計測待ち（6節）。

## 3. 残す厳密さ（変えない）

プレイヤーが「ずるい」と感じる判断は観測のみのままにする。

- 射撃の目標と発射：分隊の誰かが見た敵だけを狙い、発射直前に本人の視線判定を通す。
- 移動・迂回・突撃の行き先：分隊の表の最後に見た位置だけを使う。
- 砲撃の位置：今の規則のまま。
- 発見の遅れ：分隊として初めて見る敵には0.6秒かかる。
- プレイヤー側の表示：自軍の誰かに今見えている敵だけを出す。

## 4. 段階

各段階は試験切替 `-BattleSquadKnowledge=<n>`（既定0）で入れる。0は今の試合と同じ結果を保つ。

### 段階1：分隊の表を1か所で作る（結果は変えない）

- `Think` と `Observe` の「隊員を順に回る」読み方を、この表の参照に置き換える。
- 今の読み方は「最初に見つけた隊員の接触」と「いちばん新しい接触」が混ざっているので、置き換えは1か所ずつ、元の選び方を保って行う。
- 確認：既定の試合が置き換え前と IDENTICAL。
- 効果：コードの簡略化。負荷はほぼ変わらない見込み。
- **状況（11-24 04時20分）**：main に入れた（ebbb86b）。既定の試合は入れる前と IDENTICAL（マップI seed 7、`obs-base-I-s7` と `obs-sk1-I-s7`）。当初の案から2点変えた。
  - 表は `Think` の中でその都度作る（作り置きすると、接触が書き換わった時に古い所を指すため）。
  - `Observe` は置き換えていない（まとめた結果の並び順を側面攻撃・後退が順に読むので、結果が変わるおそれがある）。段階2で一緒に直す。
  - 切替は足していない（結果を変えない書き換えのため）。

### 段階2：分隊の中の報告をなくす（`=1`）

- 隊員が自分で見た接触は、その場で分隊の表に入る（今は16m・0.8秒遅れで1人ずつ）。
- 報告は分隊から分隊へ、敵1人につき1件だけ送る（遅れは今の0.8秒）。
- 兵ごとの表は「自分で見た接触」だけにする。報告で知った接触（`bShared`）は分隊の表だけに置く。
- 詳細は9節（11-24 に詰めた。実装はしていない）。

### 段階3：分隊が見ている敵への光線を減らす（`=2`）

- 分隊の誰かが今見ている敵には、「見張り役」の隊員2人だけが毎回光線を出す（その敵を見ている隊員のうち、番号の小さい順）。ほかの隊員は出さない。
- 分隊がまだ知らない敵には、今までどおり全員が光線を出す（発見の遅れも同じ）。
- 射撃の条件を「自分で見えている接触」から「分隊の表で見えている敵」に変える。発射直前の本人の視線判定は今もあるので、壁越しには撃たない。
- 見張り役が2人とも見失ったら、次の走査（0.2秒後）で全員が出し直す。
- 変わる動き：
  - 角を曲がった兵が、分隊が見ている敵をすぐ撃てる（今は本人の発見に0.6秒）。これは見て分かる可能性があるので、本人の射撃開始に短い反応の遅れ（値は試して決める）を残す案を併せて試す。
  - 見張り役が2人とも同時に見失うと、ほかの隊員に見えていても0.2秒だけ表示が消えることがある。
- 効果：光線の本数。上限は6節の計測で決まる。

### 段階4：見えない所の後始末に真値を使う（`=3` または別の切替）

- 倒れた敵は、数秒後に分隊の表から消す（今は記憶の5秒が切れるまで残り、そこへ走る・狙う）。
- プレイヤーには「無線で聞いた」と読める範囲にとどめる。位置・体力・移動は読まない。
- `arms` の「倒れるのを見た敵への突撃をやめる」（`-BattleArmsChargeFallen`）と役割が重なるので、入れる時に片方へ寄せる。

### 9.1 今の報告の実際（コードから分かったこと）

- 報告は分隊単位ではなく、**同じ軍の兵どうし**で回っている。見えている敵を、16m以内（`ShareRange`）の味方の兵すべてへ、0.8秒遅れ（`ShareDelay`）で送る。分隊が違っても届く。
- 送り手が見続けている間、約0.8〜1.0秒ごとに送り直す。届く前に送り手か受け手が倒れるか、16mより離れると捨てる。
- 受け取った兵の表では「見えていない・報告で知った」接触になる。兵が自分で見て覚えていた接触も、新しい報告が来ると「報告で知った」に上書きされる。
- 量（既定、30FPS）：マップI seed 7 で届いた報告は203万件、待ちの最大は9514件。マップJ seed 7 で87万件、最大9417件。
- **分隊の判断は、今でも隊員の接触を直接読んでいる**（目標選びは自分で見た接触だけ、`Observe` は隊員の中でいちばん新しい接触）。分隊の中の報告を読んでいるのは兵ごとの処理だけ：
  - 見張りの向き・歩いている兵の視線（`BattleSoldierWatch.cpp`）
  - 目標への向き・遮蔽への接近を続けるかの判定（`Follow`、`BattleCoverAction.cpp`）
  - 側面へ回る兵の見る向き
- 分隊の外から来た報告を読んでいるのは：`Observe`（側面攻撃・後退が数える脅威）、見張りの向き、プレイヤーの支援要請、画面の「記憶」の印。
- 射撃・撃ち返し・遮蔽の選び・戦車砲などは「自分で今見えている」だけを読むので、報告とは無関係。

### 9.3 認識の更新の順（`UBattlePerception::Update`、`=1` の時）

1. 兵ごとの走査（今のまま。発見の遅れ0.6秒も同じ）。
2. 期限が来た分隊間の報告を、受け手の分隊の表へ入れる。受け手がその敵を今見ているか、もっと新しい情報を持っていれば捨てる。
3. 生きている隊員の接触を分隊の表へまとめる。新しい方を採る。同じ時刻なら、今見えている方、次に番号が小さい兵の方（`Observe` の今の決まりと同じ）。「今だれかが見ているか」と「今見ている隊員」をここで付け直す。
4. 見えていない敵は古くなった分だけ確かさを下げ、5秒で消す（今の兵ごとの決まりと同じ式）。
5. 分隊間の報告を待ちに入れる（9.4）。
6. 生きている隊員がいなくなった分隊の表と報告を消す。

### 9.4 分隊から分隊への報告

- 送る条件：隊員が今その敵を見ている。長距離視界（偵察・見張り台）で見た敵は口伝えにしない（今と同じ。偵察報告で伝わる）。
- 届く相手：見ている隊員から16m以内に、生きている隊員が1人でもいる別の分隊（同じ軍）。**今の「16m以内の兵へ」と同じ届き方**で、新しい数値は増やさない。
- 遅れ：0.8秒（見ている隊員の設定値）。
- 捨てる条件：見ていた隊員が倒れた、受け手の分隊が全滅した、届く時に16m以内の隊員がいなくなった。
- 同じ組（送り手の分隊・受け手の分隊・敵）は待ちに1件まで。受け手が今その敵を見ているなら送らない。
- 件数の見込み：兵ごとの組が分隊ごとの組になり、分隊の中の分が丸ごとなくなる。8人の分隊なら、分隊の中で最大56組、隣の分隊との間で最大64組あったものが、0組と1組になる。

### 9.5 読む側の置き換え

| `FindSquadContact(分隊, 敵)`・`GetSquadContacts(分隊)`（新設） | 分隊が知っていること | 分隊の表 |

| 場所 | 今 | `=1` |
|---|---|---|
| `Think` の目標選び・持ち続け・見失い・数の比較 | 隊員が自分で見た接触 | 変えない（段階1の表） |
| `Think` の目標の位置・別の区画かの判定 | 最初に見つかった隊員の接触 | 分隊の表（いちばん新しい位置になる） |

### 9.6 変わる動き

- 分隊の中で、見た隊員の情報が**遅れなし・距離の制限なし**で全員に回る（今は16m以内・0.8〜1.8秒遅れ）。効くのは向きと移動だけ：仲間が見た敵の方を早く向く、遮蔽への接近を続ける判断が新しい位置で行われる。射撃の開始は早くならない（本人の発見0.6秒が残る）。
- 分隊の目標の位置が「最初に見つかった隊員の接触」から「いちばん新しい接触」になる。
- 見た隊員が倒れても、分隊は最後の位置を5秒覚えている。
- 自分で見た記憶が、報告で上書きされなくなる。`-BattleReacquireGrace`（見失った直後の再発見を早める）や側面攻撃の「自分で2.5秒以内に見た」の条件が、わずかに通りやすくなる。
- 別の分隊への報告は、受け手の分隊の全員に同時に届く（今は16m以内の兵だけ）。後退・側面攻撃が数える脅威が少し増える可能性がある。
- プレイヤーから見て分かるのは「仲間が見つけた敵の方を分隊がそろって向く」くらいで、ずるくは見えない見込み。画面で確かめる。

### 9.7 保存

- 経路の保存（`PlayerRoutesVersion`）と同じ形にする：`SquadKnowledgeVersion`（0＝なし）を足し、`=1` の時だけ分隊の表と分隊間の報告を書く。`=0` の保存は今と1バイトも変わらない。
- 保存と起動引数が合わない時は読み込みを断る（砲兵の試験フラグと同じ扱い）。既定にする時に、旧い保存の読み替え（兵の表の「聞いた」接触を分隊の表へ移す）を足す。
- 検証：分隊が実在して生きた隊員がいること、接触が今の検証（位置・時刻・相手の軍）を通ること、件数の上限、報告の時刻の範囲。保存の試験（`BattleMixedSaveSmoke`）に `=1` の往復を足す。

### 9.8 切替・確認・未決

- 切替：`-BattleSquadKnowledge=1`（既定0）、片側試験用に `-BattleSquadKnowledgeTeam=<0|1>`。混成（隊長＋Mass部下）だけに効かせ、旧い経路と認識の動作試験は今のまま。
- 数える値（ねらった動きの確認）：分隊間の報告の件数と待ちの最大、`Knows` が分隊の情報を返した回数。1試合で「兵ごとの待ちが0、分隊間の待ちが数百件以下」を見てから本数を回す。
- 確認の順：①`=0` が今と IDENTICAL（1試合）②`=1` の1試合で数える値 ③元の結果との差（マップ I・J、seed 2つ×左右、片側）④保存の往復 ⑤画面（分隊が角で敵を見つける場面）。
- 効果の見込み：報告の負荷 0.09〜0.16ms がほぼ0に、待ち約9500件が数百件に、保存が小さくなる。フレームの時間への効果は小さい。**段階2の主な意味は、段階3（射撃の条件を分隊の表にして光線を減らす）の土台になること**。
- 手間の見込み：実装2〜3時間＋ビルド・動作試験、比較16試合。
- 未決（ユーザーが決める）：

  2. 分隊間の届く距離は今と同じ「見た隊員から16m以内に隊員がいる分隊」でよいか（案：これ。別案は隊長どうしの距離で、計算は軽いが新しい数値が要る）。
