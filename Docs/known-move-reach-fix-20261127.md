# Reach 修正（38878dd3 に対する未コミット変更）

## 固定場面の失敗原因

`Setup/Benchmarks/KnownTargetFire-20261126/kf-38878dd-v2/run.log:2263` の採用直前の候補は、開始位置から XY 差が `(-15,-946.20)` cm。距離は約946.32cmで、`move_defend_reach_fire` の `abs(distance-1000)<50` を満たさない。その後の到着・発砲・帰還は同ログに記録されている。10mリングだけが選ばれるという試験配置の想定と、優先される壁端候補が食い違っていた。

側壁の半幅を160→120cmにして、壁端の計算位置を約989cmへ移した。候補の優先順位や本体の選択規則、既存の合否条件・許容幅は変更しない。`BATTLE_KNOWN_MOVE_REACH_FIRE` に全8条件の真偽、採用距離、候補種別、カウンタ差分を1行で記録する。

## 本体の修正

- `Follow`：DefendMarchが0でも、帰還記録が存在すれば追跡・解除する。現在の命令が変わっていても記録を取り除けるよう、現在のReach値を追跡の条件にしない。
- `StartKnownMove`：Reach専用の到着処理に入る場合も、確認済みの往路を逆順に保存する。
- `EndKnownMove`：Reach専用の到着処理を取り消す場合も、射撃FIFOのWaitingとRequestedAtを即時解放する。

追加の本体分岐は値2のReach由来の状態に限られる。Reach=0では帰路保存・FIFO解放の従来条件を維持する。DefendMarch=0かつReach=0では帰還記録を生成しないため追跡の追加条件も成立しない。値0・1の処理は変更しない。cb52363aとの試合結果の実測比較は行っていない。

- 実際に採用した往路と保存された逆順経路を全点比較する。
- Commit=0で、自由位置・到着後未発見・曲がった帰路を検査。固定した経路の両区間がカプセルで通過可能で、直進すると障害物に当たることも検査する。これは帰還実行の固定場面であり、逆順経路の保存検査は前項で別に行う。
