# 計測ロックの順番待ちを自動にする（作業の進め方の設計案）

## 1. 困っていること

- ビルド・UE の起動・計測は、CPU を共有するので1つずつしかできない（`MEASURE.md` 0-1）。今はロックをチャット（`SendMessage`）で受け渡している。
- 11-22 の夜は、ロックの順番待ちが 個人AI → Codex委任 → 区画AI → この作業 と並び、この作業は 23時55分に並んで 2時30分ごろの番になった。待つ間、ビルドも試合もできない。
- 受け渡しのたびに、渡す側・受ける側の Claude がメッセージを書く・読む手間（使用量）がかかる。持ち主が寝てしまう（ターンが終わる）と、次の番に渡らないことがある。
- 誰が持っているか・あと何分かが、チャットの履歴をたどらないと分からない。

## 2. 案：ファイルで持つロックと順番待ちの列

`Setup/Lock-Queue.ps1`（PowerShell。どのセッションからも同じものを呼ぶ）。

| 呼び方 | 働き |
|---|---|
| `Lock-Queue.ps1 -Join -Who <セッション名> -Purpose <用途> -Minutes <見込み>` | 列の最後に並ぶ。列と持ち主は `C:\Users\nanek\Documents\FPS\.lock\queue.json`（作業ツリーの外。どの作業ツリーからも同じ場所） |
| `Lock-Queue.ps1 -Wait -Who <名>` | 自分の番になるまで待つ（30秒ごとに見る）。番が来たら持ち主に自分を書いて終わる。Claude は `run_in_background` で呼び、終わりの通知で番が来たと分かる |
| `Lock-Queue.ps1 -Release -Who <名>` | 手放す。次の人が持ち主になる |
| `Lock-Queue.ps1 -Status` | 持ち主・始めた時刻・見込みの終わり・列を表示 |

- **期限**：持ち主が見込みの時間＋30分を過ぎても手放さず、その間に UE・ビルドのプロセスが動いていなければ、次の人に渡す（寝てしまった持ち主で列が止まらないように）。動いていれば延長して、持ち主へメッセージを送る案内を出す。
- **割り込み**：ユーザーの画面での確認（プレイ）は最優先。`-Join -Urgent` は列の先頭に入る（持ち主の作業は止めない）。
- **記録**：受け渡しの履歴を `queue-log.jsonl` に残す（何分待ったか・何分使ったかが後で分かる）。
- 既存の決まり（他のセッションのプロセスを止めない、実行を重ねない）はそのまま。ファイルのロックは「目印」で、強制はしない。

## 3. 移行

1. スクリプトを main に入れ、`MEASURE.md` 0-1 の手順を「`Lock-Queue.ps1 -Join` → `-Wait`（裏で）→ 作業 → `-Release`」に書き換える。
2. 各セッションへ一度だけ周知する（以後はメッセージでの受け渡しは不要。急ぎの相談だけメッセージ）。
3. `/measure` スキルの段取りにも入れる。

## 4. 合わせて考えたいこと

- 描画なしの試合は並列で回せるので、短い確認（1〜2試合）を「相乗り」できるようにする案：持ち主が許せば、列の次の人の描画なしの試合を同時に流す（`-Share` で「相乗り可」を示す）。CPU の空きを使えるが、時間の比較には使えない試合になるので、勝ち負けの比較や一致の確認だけに限る。
