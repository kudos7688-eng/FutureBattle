# 通れない地形（山・湖・崖）と新しいマップJ（設計案）

2026-11-22 1時20分 Claude（ロードマップに従う改善活動）。**設計のみ。未実装。** ユーザーの要望（11-22）「新しいマップの実装」「通行不可能な山や地形要素も将来的に欲しい」による。既存のマップ（A〜I）は変えない。マップの規則と区画の決め方は ROADMAP 11-19「区画の命令とマップH」（1000m×700m、50m の区画、180度回転の点対称、入れる建物は1区画に1つまで）に合わせる。数値と配置は叩き台で、採用・配置の好みはユーザーが決める。

## 1. 今ある材料

| 材料 | 今の使われ方 | 根拠 |
|---|---|---|
| 歩けない領域 | マップH・I の川。経路網から外す体積（`ANavModifierVolume` ＋ `UNavArea_Null`）で、橋と浅瀬だけ渡れる。見通しは通る | `BattleMapCommandlet.cpp` の `RiverNoWalk` |
| 区画の表 | マップI は 20×14 区画を1文字ずつの表で持ち、生成と規則（拠点・高さ・道）を同じ表から作る | `BattleMapI.h`・`BattleMapLayoutI.inl` |
| 高さ | 丘・2階は歩ける面（`FHeightPatch`）。目的地は地面から上下2mで探すので、2mより高い所には行けない | `BattleTerrain.h`、`Docs/design-height-tactics.md` |
| 区画の点数 | 川（`R`）は守る区画にしない（`Cover('R')=-100`）、区画経由の移動も止まらない | `BattleFrontLine.cpp`、`BattleSectorRoute.cpp` |

## 2. 地形の種類（区画の表の文字。マップJ以外の区画マップでも使える形にする）

| 文字 | 種類 | 移動 | 見通し・射撃 | 作り方 | AI（区画） |
|---|---|---|---|---|---|
| `M` | 山（岩山） | **通れない**（歩兵・車両とも） | **遮る**（向こうは見えない、撃てない。間接射撃は越える） | 区画いっぱいに段々の箱を積む（下から 12m・9m・6m、各段で一回り小さく）。足元に経路網から外す体積。歩ける面の印（`BattleTerrain` タグ）は付けない → 山の足元に遮蔽位置ができる | 守る区画にしない、区画経由の移動で通らない。山の隣の区画は「背後を守られた区画」として遮蔽の点を少し上げる |
| `L` | 湖・深い水 | **通れない** | 通る（平らな水面） | 川と同じ（水の色の板＋経路網から外す体積） | 守る区画にしない、通らない |
| `C` | 崖の上の台地（第2版） | 歩ける。**上がれるのは坂の区画 `r` だけ** | 高い所から見下ろせる | 高さ6mの平らな面（`FHeightPatch`）と、坂の区画の面。崖の縁は高さの差で上がれない | 守る区画として高さの点を足す（段階7）。**2mを超えるので `-BattleTerrainGoal`（段階7の 3.2）が先に要る** |
| `X` | 密林・沼（将来） | 通れるが遅い（0.5倍） | 密林は遮る、沼は通る | 速さを変える領域。手で動かす部下の速さの表が要る | 急ぎの移動では避ける |

第1版は `M` と `L` だけ（どちらも今の材料だけで作れる）。`C` は段階7の 3.2 の後、`X` はさらに後。

## 3. マップJ（第1版の叩き台）

**狙い**：山で戦場を3本の道（北の峠道・中央の谷・南の峠道）に分け、道どうしは峠（山の切れ目、幅1区画＝50m）でだけつながる。戦略層（`Docs/design-strategy-layer.md`）の「戦線」が地形そのものになり、どの道に集めるか・峠を押さえるかが意味を持つ。

- 広さ・区画：1000m×700m、20×14区画（H・I と同じ）。本拠地は東西の端（I と同じ位置 `S`）。
- 東半分（列10〜19、x=0〜500m）の表。西半分は180度回転：
  ```
  行13  TFTFHFTFTF   北の道（外側）
  行12  FHFTOHFTFT   北の道の拠点 O（列14）
  行11  TFHFTFHTFF
  行10  MMMFMMMTHF   北の山脈。峠は列13（F）
  行 9  HLLHPHFHFT   中央の谷、湖 L（列11〜12）
  行 8  HLLPHTHSSS
  行 7  OHHPHFTSSS   中央の拠点 O（列10＝町の広場）、本拠地 S
  行 6  HPHHFTHSSS
  行 5  HHWHTFHSSS
  行 4  PHHFTHFTFT
  行 3  MMMFMMMMTF   南の山脈。峠は列13
  行 2  FHTHOTTFTF   南の道の拠点 O（列14）
  行 1  TFHhhFTFFT
  行 0  TFThhTTFTF
  ```
  （文字は I と同じ：H 2階建ての家、W 倉庫、P 広場、O 拠点、F 畑、T 林、h 丘、S 本拠地。加えて M 山、L 湖）
- 回転すると、行3と行10の山脈は西半分にも続き（列3〜9）、峠は西に列6、東に列13の2つずつ。本拠地の近く（列0〜2、17〜19）は山が無く、本拠地から3本の道のどれにも出られる。
- 拠点（列,行）：北の道に (14,12) と (5,11)、中央に (10,7) と (9,6)、南の道に (14,2) と (5,1)（東半分の3つと、その180度回転の3つ）。ほかに集積所を本拠地寄りに1つずつ置くかは試してから。
- 全体で見ると、行10は列2〜16、行3は列3〜17が山で、峠は列6と列13の2つずつ。
- 道（舗装路）：中央の谷を東西に1本、峠を通る南北の短い道。北・南の道は畑と林の農道。
- 戦車：峠は幅50m で戦車も通れる。湖は通れない。

## 4. 確かめること（生成の後）

| 確かめること | 方法 | 目安 |
|---|---|---|
| 山と湖が通れない、峠と道は通れる | 生成のときの自己検査（川の検査 `SECTOR_MAP_RIVER` と同じやり方で、山を挟んだ2点の経路が峠を回ること、湖の中に立てないこと） | `SECTOR_MAP_RESULT failures=0` |
| 山が見通しを遮る | マップの数値監査（`Test-MapStats.ps1 -Map J`）の視線の長さ。山を挟んだ区画どうしの見通しが0 | ― |
| 区画の命令 | `-BattleSectorAudit`（全区画への命令の受け付けと到着） | 山・湖の区画は命令を受け付けない（拒否の理由を出す）。ほかは I と同程度 |
| AI の試合 | 3 seed で完走、西東の勝ちの偏り（12戦で4:8より偏らない）、3本の道それぞれで戦闘が起きるか | ― |

## 5. 実装の順と所要（ロックが要るのは 3 と 4）

1. 区画の表 `BattleMapJ.h`（I を写して `M`・`L` を足す）と配置 `BattleMapLayoutJ.inl`、`FMapDef` に `Lvl_BattleWide_J`。区画のコードで `M`・`L` を「守らない・通らない」にする（`Cover`、区画経由の移動、前線の行に山がある場合の扱い）。— ロック不要、約1時間。
2. ミニマップと作戦画面の格子に山（茶の濃い色）と湖（青）を描く。— ロック不要。
3. 生成（`BattleMapCommandlet`、UE を起動）と自己検査、区画の監査。— ロックが要る、約20分。
4. Test-Battle、マップJ の試合3本。— ロックが要る、約20分。

触るファイルは区画AI・マップの担当と重なる（`BattleFieldLayout.h` の表、`BattleMapCommandlet.cpp`、`BattleSectorRoute.cpp`、`BattleFrontLine.cpp`）。既存マップの試合を変えないこと（A・E・I の一致）を確かめ、担当に声をかけてから main へ入れる。

## 6. ユーザーに決めてもらうこと

- この形（山脈2本で3本の道、峠は各2つ）でよいか。山の量（区画の何割）、峠の幅（50m／100m）。
- 拠点の置き方（峠そのものに拠点を置くと、峠の取り合いが中心になる。今の案は峠の先に置く）。
- 崖・台地（`C`）を第2版で入れるか（段階7の 3.2 が先に要る）。
