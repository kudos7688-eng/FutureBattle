# 地形を使う AI：道・峠・湖（マップJ と区画マップ全般の設計）

2026-11-22 1時40分 Claude（ロードマップに従う改善活動）。**設計。1の一部（戦線の分け方）だけ実装する（下の 6）。** マップJ（`Docs/design-map-j-terrain.md`）で、山脈が戦場を3本の道に分け、道どうしは峠（幅50m）でだけつながるようになった。今の AI は「通れない地形」を前提にしていないので、そのままでは峠や道の意味を使えない。戦略層（`Docs/design-strategy-layer.md`）・部隊群・前線軍・区画AIの順に、何が足りないかと直し方を決める。

## 1. 今の AI が地形をどう扱っているか

| 層 | 今 | マップJ で起きること |
|---|---|---|
| 戦略層の戦線 | 拠点にいちばん近い場所（直線距離のボロノイ） | 山の向こう側の区画が手前の拠点の戦線に入る。山越しに見えない敵が「その戦線の敵」として数えられる |
| 戦略層の「集めやすさ」 | 拠点どうしの直線距離で近い2つの戦線 | 山を挟んで直線では近いが、峠を回ると遠い戦線を「隣」とみなす |
| 区画経由の移動 | 隣の8区画から遮蔽の多い区画を選び、川には止まらない。11-22 に山・湖も止まらないようにした | 道のりは経路網が決めるので峠を通る。ただし「峠は危ない」は知らない |
| 前線軍 | 区画の行ごとに1本の線。11-22 に山・湖の区画を持ち場にしないようにした | 山の行は持ち場が無く、線が途切れる（それ自体は正しいが、峠を守る意識が無い） |
| 攻撃群の目標 | 自軍のものでない拠点のうち本拠地にいちばん近いもの（直線） | 山の向こうの拠点を「近い」と選び、峠を回って遠回りする |
| 見張り所 | 地図ごとの固定の点（マップJ は北と南の丘） | 峠の出口を見る見張りが無い |

## 2. 地形の図（地図ごとに開始時に1回作る。正規の地形だけで、敵の情報は使わない）

- **通れる区画**：区画の種類が `M`・`L`・`R`（川）でないもの。川は橋・浅瀬の区画を通れるとみなす（マップH・I）。
- **区画の道のり**：通れる区画どうしを上下左右（斜めは両側が通れるときだけ）でつないだ図の上の、区画の数で数えた距離（幅優先探索）。
- **領域**：峠の区画を取り除いたときにつながっている区画のまとまり（マップJ では北の道・中央の谷・南の道と、本拠地の脇の空き地）。
- **峠**：その区画を取り除くと、2つの領域が分かれる区画（マップJ では4つ）。峠ごとに「つなぐ2つの領域」と「出口の区画（両側）」を持つ。
- 作り方：区画の種類の表（`FMapDef::SectorKind`）から作る。経路網や視線判定は使わない（開始時に 280 区画の幅優先探索を数回）。

## 3. 戦略層での使い方

1. **戦線は区画の道のりで分ける**：各区画を、道のりでいちばん近い拠点の戦線にする（同じなら番号の小さい拠点）。山の向こう側は別の戦線になる。両本拠地の150m は今までどおり別。（6 で実装）
2. **隣の戦線**：区画が接している戦線どうしを隣とする（峠でつながる戦線も隣）。「集めやすさ」（自軍の戦力）はこの隣で数える。（6 で実装）
3. **集中先の点数に道のりを使う**：自軍の前線からの距離を直線でなく区画の道のりにする（100m＝2区画あたり −1.0 のまま）。
4. **峠の評価**：集中先へ行く道が峠を通るとき、その峠の出口に知っている敵がいれば −5（隘路で待ち伏せされる）。峠を通らずに行ける戦線があれば、そちらを優先しやすくなる。
5. **見張り**：峠の出口（相手側）を見られる区画を「見張りの候補」にし、偵察組を置く（戦略層 S2 の 7）。山で見えない戦線は「不明」になりやすいので、峠の見張りが情報の主な入り口になる。

## 4. 部隊群・前線軍での使い方

- **峠の守り**（保持 S3 の拡張）：自軍の拠点がある領域へ通じる峠の出口（相手側）に、知っている敵が集まっていたら（3人以上・20秒）、その峠の自軍側の出口の区画を「保持」にする。重装歩兵・対戦車班を優先して置く（隘路は少数で止められる）。
- **前線軍**：線が途切れる山の行では、峠の区画とその自軍側の出口を持ち場にする（峠は前線の一部として守る）。今は山の行を持ち場にしないだけなので、峠の持ち場は無い。
- **攻撃群**：目標の拠点が別の領域にあるとき、集結点をその領域へ通じる峠の自軍側の出口にする（峠を抜けてから集まるのではなく、手前で集まってから抜ける）。峠を抜けるときは、迫撃砲・自走砲が群にいれば、峠の出口の知っている敵を先に撃つ（`-BattleGroupFireSupport` の対象を峠の出口にする）。
- **奇襲群**：北と南の道（山の外側）を、山で見えないまま進める通り道として使う。今の「端の行」を「知っている敵の少ない道の領域」に置き換える。

## 5. 確かめ方

- マップJ で、戦略層 S2 あり／なし、峠の守りあり／なしの片側試験（`Run-StrategyScreen -Maps J`）。
- 読む値：3本の道それぞれの戦闘の量（撃破の位置）、峠での死傷、拠点の保持時間、得点の差。山を挟んだ見通しの無い戦線の「不明」の割合（`BATTLE_SITUATION`）。

## 6. 今回の実装（ブランチ `strategy`）

- 戦略層の戦線の分け方を、区画のある地図では区画の道のり（3-1）に、隣の戦線を接している戦線（3-2）にした。区画の無い地図（A〜G）は今までどおり直線距離。戦略層の切替（`-BattleStrategy`・`-BattleSituationLog`）が 0 なら呼ばれないので、既定の試合は変わらない。
- 11-22 12時50分：集中先の点数の「自軍の前線からの距離」を区画の道のりにした（3-3、bf2a96b、main 8097aeb）。
- 11-22 14時40分（未ビルド）：**峠の評価**（3-4）を試験切替 `-BattleStrategyPass=1`（既定0、条件名 `ST2P`）にした。
  - 峠の見つけ方は 2 の定義（取り除くと領域が分かれる区画）をやめ、「左右か上下のどちらか一方だけが、通れない区画（山・湖・川）か地図の端でふさがれている、通れる区画」にした。マップJ の山脈は本拠地の脇（端の2〜3列）で切れていて、峠を取り除いても領域は分かれないため。マップJ では峠は4つ。マップH・I では橋・浅瀬の区画が峠になる（隘路という意味では同じ）。出口は、ふさがれていない向きの両隣。
  - 峠とその出口にいる知っている敵（新しい目撃は1、記憶は 1−経過/90秒 の重み。戦線と同じ数え方）が 1 以上なら、その峠は「危ない」。危ない峠を通れないものとして、集中先から自軍の前線（本拠地と自軍の拠点）までの道のりを測り直し、もとの道のりより4区画（200m）を超えて遠くなる（または行けなくなる）集中先は −5。
  - 記録は `BATTLE_STRATEGY_PASS`（見直しのたび。峠の数・危ない峠の数・−5 になった拠点のビット）。
- 残り（見張りを峠の出口に置く 3-5、峠の守り・前線軍の峠の持ち場・攻撃群の集結点・奇襲群の道 4）は、峠の評価の効き目を見てから。
