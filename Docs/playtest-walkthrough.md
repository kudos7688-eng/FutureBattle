# 通しの試遊手順：区間指定 → 攻撃群 → 補給 → FPS 操作 → RTS へ戻る

2026-11-25 作成（系統「評価の道具」）。`Docs/review-2026-11-25/03-development-policy.md` 2.6 と `05-standard-practice-comparison.md` の「費用が小さく効果が大きい順」1番の手順。
目的は勝ち負けではなく、**指揮 → 交戦 → 補給 → 個人操作 → 指揮へ戻る、が1本の試合の中でつながるか**を確かめること。所要は30〜40分。

- 操作の正本は `PROTOTYPE.md`。この文書は順番と「何が起きれば合格か」だけを書く。操作が変わったら PROTOTYPE を直し、ここは段階の表だけ合わせる。
- 各段階は **できた／できない／意図が分からない** のどれかに丸を付ける。「意図が分からない」は、操作はできたが何のための機能か・今どうなっているかが画面から読めなかった場合。
- 途中で詰まったら、その段階に「できない」を付けて次へ進む（前の段階ができなくても、次の段階は単独で試せるように書いてある）。

## 0. 使うマップと起動

**マップI**（`Lvl_BattleWide_I`、50mの区画・町と畑と林・川と橋・丘）を使う。H・I・J から I を選んだ理由：

1. 区画AI の組み合わせ（区画経由・側面・被弾反応など9個）が既定ON になっているのはマップI だけで、今の AI のいちばん進んだ状態が出る（STATUS 要約「区画AI」）。
2. 評価の試合の大半がマップI で、B06（補給の後に区画任務へ戻る）で既定の試合が変わったのもマップI。試遊で見たことを計測の結果と突き合わせやすい。
3. 町の塀・家があり、壁遮蔽（C）を試す場所に困らない。前線の区間は4つできる（`Docs/design-front-strategy.md` 段階1〜2の結果）。
4. 起動のたびにマップを作り直す手順（H・J の `Initialize-Map*.ps1`）が無い。

J を選ばなかった理由：区間ごとの前進・後退の自動確認（`ord-J7-b`）は J で行ったが、J は山で道が3本に分かれ、区画AI の組み合わせも既定ではないので、通しの代表にはしない。**段階4（区間の前進・後退）がマップI で「できない」だったときだけ、同じ段階を J でもう一度試す**（下の2つ目のショートカット）。H は作り直し前の比較用で、小隊8人での詰まりが残っている。

| 起動 | 中身 |
|---|---|
| デスクトップ「FutureBattle 通し試遊（区間・攻撃群・補給・FPS） マップI」 | `Setup\Play-Area.ps1 -Map I -SectionOrders` |
| デスクトップ「FutureBattle 通し試遊（区間の前進・後退だけ） マップJ」（段階4の予備） | `Setup\Play-Area.ps1 -Map J -SectionOrders` |

`-SectionOrders` が足す試験切替（購入予約 `-BattleHireReserve` だけはもともと既定1。ほかは既定0で、自軍＝チーム0だけ）：`-BattleFrontSectionOrders=1`、`-BattleFrontPlan=1`、`-BattleFrontPlanTeam=0`、`-BattleFrontPlanPlayer=1`、`-BattleFrontPlanFocus2=1`、`-BattleHireReserve=1`。区画のあるマップなので `Play-Area.ps1` がいつもの試遊の条件（`-BattleSectorAI=1`・`-BattleSectorMove=1`・`-BattleGroupSectors=1`・`-BattleFrontReserve=1` など）も足す。敵の AI はいつもの既定のまま。

始める前に：ビルドや計測をしているセッションがあるときは起動を重ねない（`Setup\Lock-Queue.ps1 -Status`。ユーザーの試遊は `-Urgent` で列の先頭に入れる）。

**先に知っておく制限（2026-11-25 11時の main）**

- 攻撃軍は、区間の前に取れる拠点が見えるまで重点へ向かわない（画面にもその注意が出る）。
- 第二の重点は、自動の試合では一度も選ばれていない（条件がそろわない）。プレイヤーが2区間を「重点」に指定したときの動きは未確認。
- ゲームパッドは作戦方針の欄に未対応。この手順はキーボードとマウスで行う。
