# save batch D（2026-11-21）

## 実装範囲

- S05：Mixed / Area の全個体（退役者を含む）について、兵種の `Weapon(Type, Slot)` が生成し得る武器と照合。補充者は旧個体の武器を引き継ぎ、退役者には現在のスロットがないので、現在の配列位置との一致は要求しない。HP は `BattleSquadType::MaxHealth` に抽出した既存の `MaxHealthOf` の式と照合する。隊長倍率、車両・外骨格の例外は元の式のまま。
- 弾倉は `Capacity`（生成時の最低1発を含む）、予備弾は `ReserveFor` と照合。`AddReserve` / `MoveReserve` も同じ予備弾上限を使用している。装填中の弾倉・予備弾を別々に許可し、盾・ランチャー・SPG弾の既存の兵種別検査を維持。旧全Actor形式の特殊初期HPは従来の許容範囲を維持する。
- S10：`LoadDataFromSlot` で取得した生バイト列を共通の `BattleSaveValidation::Decode` に渡し、64 MiB超を `LoadGameFromMemory` より前に拒否する。既存スモークのメモリ復元も同じ入口へ変更。書き込みも同じ上限を確認してから `SaveDataToSlot` を呼ぶ（上限超で既存スロットを書き換えない）。新しい失敗文言は `BattleUIText.cpp` に日本語訳を追加。
- S11（一部）：雇用・補充・Plannerの個体レコード上限（Area 1000 / Mixed 500）を共有定数化し、保存側も共有。Areaの部隊数は1人部隊を考慮して個体上限以内、補充待ちは在籍人数以内とする。マップの `MatchSeconds` を保存時計上限に反映（従来fixture用の1000秒の余裕を残し、絶対上限86400秒）。装填時間、射撃間隔、照準変更待ちを実効武器設定から取得し、時間には86400秒、弾薬には100万発、個体HPには10億の絶対上限を置く。これらの絶対上限を超える設定は保存対象外。

ゲームの人数・時間・戦闘規則の値そのものは変更していない。既定試合と80秒往復保存の不変性は未実行のため未確認。

## 見送り・残件

- S06：見送り。現行 `RulesKey` は全ルールの信頼できる識別子ではない。限定prefixの生引数とConfigの列挙であり、区画・姿勢等の切替や同名マップの内容版を網羅しない。これを通常保存へ転用して「ルール一致を保証した」とは扱わない。署名を持たない旧保存の受理方針は変更せず、`BattleSaveRulesCheck` も今回未導入。
- S07：見送り。`RifleMembers` だけなら正規化できるが、現行キーが含むDepot・Intel・WarScore・陣営別戦略などの設定は複数の実行関数内で解決され、共通の実効設定表がない。生引数を一括削除したり、一部のgetterだけに置き換えると、従来区別した異なるルールを同一視する。まず全対象の解決済み値を副作用なく取得する共通契約が必要。CompositionPolicy=2 / CombatStateVersion=4 と旧v4の受理方針は今回変更していない。
- S11の経済・観測能力・戦術標本等、今回の変更範囲外にも固定上限は残る。全ての調整値で正常保存を保証したものではない。
- S10の上限は生バイト取得**後**・UObject復元**前**。ファイル全体のバッファ割当を防ぐものではなく、64 MiB以内の破損した配列長等についてUE codecの安全性を証明するものでもない。

## 訂正：S10 の上限を 1 GiB に（2026-11-22）

64 MiB の上限は、マップA の正常な保存を断っていた。マップA・30FPS・`-RoundTripSave` の試合が、80秒目の保存で毎回 `BATTLE_MIXED_SAVE_SOAK_RESULT failures=1 message=Save file exceeds size limit` になった（実装計画ロードマップの報告。main 216dd58・90a2dc5 の凍結ビルド。E・F・H・I は合格）。取り込みの確認をマップE だけで行ったため、見落とした。マップA は兵が最も多く、観測の記録（観測者×相手）がタグ付きの形式で保存されるので、正常でも大きい。

直し：`BattleSaveValidation::MaxBytes` を 1 GiB にした（ありえない大きさのファイルを読む前に断る役目は残す）。保存のたびに `BATTLE_SAVE_BYTES slot=… bytes=… limit=…` を出す。スモーク試験は上限ちょうどの配列を作らず、小さい上限（4096）を渡す `Decode(Bytes,Error,Limit)` で同じ検査を確かめる。画面の文言も「1 GiB」に。保存の中身は変えないので、試合の結果は変わらない。
