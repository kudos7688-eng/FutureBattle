# 進行中の実験（試験切替）の一覧

2026-11-25 作成（系統「評価の道具」）。`Docs/review-2026-11-25/05-standard-practice-comparison.md` ④「切替に期限と持ち主がない」への対応。

- **対象は進行中の実験だけ**：`STATUS.md` の要約に出ていて、既定0（または試験の値）のまま採否が決まっていない切替。`SWITCHES.md`（約500個、自動生成）の全部ではない。既定になったもの・削除したもの・診断や計測用の引数・恒久の設定（`=0` で切れる既定ONの機能）は載せない。
- **見直し日は強制の採否の期限ではない**。その日に担当の系統が「採用をユーザーへ諮る／削除を諮る／休止（再開の条件を書く）／見直し日を延ばす（理由を書く）」のどれかを選び、この表の行を書き換える。既定にするか・消すかを決めるのはユーザー。
- **新しい試験切替を足すときは、この表に1行足す**（`AGENTS.md`）。行を消すのは、既定になった・削除した・休止を2回続けて延ばしてユーザーが打ち切りを決めた、のとき。消すときは STATUS に結果を1行残す。
- 見直し日の初期値は、この表を作った系統が一律に置いた（2026-12-09＝2週間後。依存の修理待ちは「修理の後」）。**担当の系統が自分の行を直す**。終了条件の「未定」は、記録から読み取れなかったもので、担当が書く。
- 発動0回の試合も集計に入れ、契約・局所の挙動・通常の試合・操作の体験を別の合格条件にする（`Docs/test-map.md`）。壊れた状態・前提の切れた状態で出た「効果なし」は削除の根拠にしない。

## 3. 行の書き方（新しい切替を足すとき）

1行に次を書く。分からない欄は空にせず「未定」と書く。

- **切替**：引数の名前と試す値。
- **担当の系統**：STATUS の要約の系統の名前。
- **目的**：何がどうなれば成功か（ねらった行動）。
- **依存する切替・前提**：これが無いと働かない切替、先に要る修理、対象のマップ。
- **見直し日**：作った日から2週間以内。依存の修理待ちなら「〜の後」。
- **終了条件**：採用を諮る条件（どの合格条件で・基準との差が何で）、削除を諮る条件、休止するときの再開の条件。発動を数える記録の行（`Analyze-MatchDelta.py --count` に渡せる形）もここに書く。
