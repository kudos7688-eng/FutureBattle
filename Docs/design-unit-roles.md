# 兵種の役割の表（10兵種）

2026-11-25 作成（系統「評価の道具」）。`Docs/review-2026-11-25/05-standard-practice-comparison.md` の4番「数値の試験を再開する前に相性表を1枚」。

- これは**確かめる仮説の表**で、完成したバランス表ではない。射程・遮蔽・近づくまでの時間・補給・買う時期が効くゲームなので、火力÷費用だけで価格を決めない。
- **数値は変えていない**。人数・費用・上限は 2026-11-25 の main のコードの既定値（`BattleState.h` の `UBattleTuning`、`BattleState.cpp` の `BattleSquadType`）を写しただけ。数値を変えたら、この表ではなくコードが正で、表を合わせる。
- 欄の中身は、決まっていること（ROADMAP のユーザー決定、`Docs/design-composition-ai.md`、STATUS の記録）だけを書いた。**決まっていない欄は「未定」**。推測で埋めていない。
- 引き算の試験（`-BattleAreaAllTypes`・`-BattleAreaWithout`、`Docs/design-subtraction-eval.md` の W1〜W9）はまだ結果が無い。出た結果は「兵種の強さ」ではなく「その購入・運用込みの損得」と読む（ROADMAP 要約）。
- 「確かめる固定場面」は、その役割が成立するかを短い場面で問うもの。今ある試験は `Docs/test-map.md`。無いものは「無し」と書き、作るかどうかは各系統が決める。

## 2. 表から読める「次に確かめる問い」

数値の試験を再開する前に、兵種ごとにこの順で問う（`Docs/test-map.md` の「契約 → 局所の挙動 → 通常の試合」）。

1. **役割の文が無い兵種**：装甲車・自走砲（主な仕事が未定）、重装歩兵・小銃小隊（得意な相手が未定）。数値を動かす前に、役割を1行で決める（ユーザーの判断）。
2. **役割はあるが成立を確かめる場面が無い兵種**：対戦車班（知ってから撃破まで）、迫撃砲班（観測から着弾まで）、外骨格兵（小銃の集中で倒せるか）、補給車（補充の通し）、偵察組（報告が使われるか）。
3. **AI が既定で買わない兵種**（偵察組・外骨格兵・補給車）：`Keep` を増やす前に、2 の場面で役割が成立することを確かめる（補給へ着けない状態で補給車の購入量を比べない）。
4. **止めている調整**：外骨格兵の値・装甲車の改善（11-25 ユーザー判断）。再開の条件は未定。
5. 引き算の試験 W1〜W9 は、1〜3 が済んだ兵種から回す。偵察組（W2）は情報を使う仕組みが無いと価値が出ないので参考値。
