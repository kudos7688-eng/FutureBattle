## 2. 方針

**数値の利点を足す前に、AI が高所を使うようにする**。高い所からは低い壁越しに見えるので、そこに立つだけで見通しの利点はすでに生まれる。数値の利点（命中など）は、使い始めてから足りなければ足す。

## 3. 中身（順に。すべて試験切替・既定0。A〜F は表が空なので処理を通らない）

### 3.1 ミニマップに丘と家（表示のみ）
- 高さの表の面を、ミニマップに高さで濃さを変えた四角で描く（丘は茶、家は灰）。作戦画面の区画の格子と同じ色づけ。
- 試合は変わらない。描画ありで画面1枚を撮って確かめる。

### 3.2 2m を超える高さへの目的地（`-BattleTerrainGoal=1`）
- 目的地を探す前に、その (X, Y) の地面の高さを高さの表（`FHeights::Ground`）で引き、その高さから上下2mで探す。表が空のマップでは今と同じ。
- これで、5〜10m の尾根（ROADMAP 11-19 のマップHの決定「高い丘・尾根（5〜10m）まで」）を目的地にできる。マップH・I の丘を高くするのはこの後。
- 確かめ方：G・H・I で全区画に命令を出す区画の監査（`-BattleSectorAudit`）の受け付けと到着が減らないこと。A・E・F の試合が一致すること。

### 3.3 区画を選ぶときに高さを見る（`-BattleHeightSector=1`）
- 区画経由の移動（`SectorStage`）と前線軍の持ち場（`BattleFrontLine` の区画の種類の点数）で、**守る・待つ**ときだけ、区画の中の高い所（丘の上、2階）の高さに応じて点を足す：1mあたり +0.5（最大 +3）。進むときは足さない（高所に寄り道しない）。
- 高い所の目安は、区画の中の高さの表の面の最高点（開始時に区画ごとに1回計算する。追加の視線判定は無し）。

### 3.4 到着位置で高所に兵を置く（`-BattleHeightSlots=1`）
- 部隊が守る区画に2階や丘の上の遮蔽位置があれば、最初に2〜3人をそこへ割り当てる（見張りと射撃の役）。残りは今の規則のまま。
- 2階の窓の高さの壁が遮蔽になるので、「しゃがんで隠れ、立って撃つ」（11-15 の低い遮蔽の使い方）がそのまま働く見込み。

### 3.5 高所の利点の数値（3.3・3.4 の結果を見てから）
- 候補：撃つ側が相手より2m以上高いとき、相手の低い遮蔽（しゃがんで隠れる遮蔽）の効果を半分にする（上から見下ろされる）。散らばりは変えない。
- 地形の形による見通しの利点と重ならないように、まず 3.3・3.4 だけで「高所からの射撃の割合」「高所にいる兵の被弾・撃破」を測り、足りないと分かってから入れる。

## 4. 確かめ方

- マップI（主の区画マップ）と G で、3.3＋3.4 の片側試験（`Run-StrategyScreen`、遮蔽行動ON）。
- 読む値：高所（地面から1.5m以上）からの射撃の割合と命中、高所にいた兵の延べ時間・被弾・撃破、区画の保持時間、得点の差。新しい記録の項目は `metrics.json` に足す（足すときは `Compare-MatchResults.py` で、片方にしか無い項目を比べない扱いにする）。
