# 守りの配置と、激しい区画への計算の集中（設計、2026-11-25、未実装）

ユーザーとの相談（11-25 9時〜）で決めた仕様。数値は仮。

## きっかけ

- 武器機能の片側試験で、普通の小銃小隊の躍進は、どの条件でも損になった。損になったのは、知らされた敵へ走る場合も、見えている敵へ走る場合も、守る小隊の20m以内の躍進も同じだった（`design-infantry-arms.md` の「片側試験」「迎え撃ち」）。
- 守る側は「敵へ近づく」のではなく、小隊として兵を散らして置き、敵が片側へ躍進してきたら反対側が撃てるようにするべき（ユーザー）。
- TPS で見たときに没入感があるよう、守りは機能する仕組みにする。全体（前線）は簡単に計算し、躍進や攻防の激しいところに計算資源を集める（ユーザー）。

## 段階1：守りの配置（散らして置く）

- 守る任務の小隊が対象。攻める小隊の躍進は変えない。
- 小隊長が「敵の来る向き」を決める。材料は、観測した敵の位置と、区画の前線の向き。
- 兵を2〜3組（左・中・右）に分け、来る向きと直角の線の上に、組どうし10〜15m離して遮蔽に置く。
- 場所の良さは、敵が躍進してきそうな遮蔽を斜めから見られる数で測る。敵が躍進してきそうな遮蔽とは、敵とこちらのあいだにあり、正面からは敵を隠すが横からは隠さないもの。
- 一度置いたら動かない。来る向きが45°以上変わったときだけ置き直す。
- **遮蔽が少ない場所では、散らして置けない。それを補う仕組みは入れない。** 守りが弱い場所は弱いままにして、地形による有利・不利（戦略性）にする（ユーザー）。

## 段階2（後で）：躍進に対して横から撃つ

- 敵の躍進に気づいたら（走り込みの見張りの仕組み）、小隊の中で知らせ合う。
- 近づかれた側の組は、遮蔽にとどまって身を低くする。反対側の組は、躍進の行き先を横から撃つ。
- 攻める側の援護射撃（`-BattleArmsCoverFire`）の、守る側の版。
- ユーザーは、ほかの仕組み（区画の割り当て・陣形）とぶつかることを懸念している。作る前に、どの兵を誰が動かすかを決める。

## 計算を集める区画の選び方

単位は区画（H・I・J・K）。区画の無いマップ（A〜E）では、詳しい計算をしない。詳しく計算する区画では、段階1の配置の評価を2秒おきに行い、段階2をする。簡単な区画では、決めた配置を保ち、評価は10秒おきにする。1人ずつの遮蔽探しは、どちらの区画でも今までどおり。

上から順に優先する。

1. **プレイヤーの周り**：必ず詳しく計算し、上限の数には入れない。
   - プレイヤーの位置から半径40mの円にかかる区画を、すべて詳しく計算する（区画は50m四方なので、位置によって最大9区画。11-25 に「最大4」を訂正）。区画の境で戦っていても、両側が詳しくなる。
   - プレイヤーが離れても、10秒は詳しいまま続ける。
2. **攻撃指示の区画**：群の仕組みと結び付ける。上限は両軍あわせて6区画。
   - 攻撃の群（`FBattleGroup` の種類0の突入群、種類2の奇襲群）が前進の段階にあるとき、次の2つの区画を詳しく計算する。
     - 目標の拠点がある区画
     - 集合地点から目標へ向かう道の、最後の1区画
   - 詳しくなるのは、**攻める側の小隊だけ**。
   - **守る側の小隊は、守る側自身が観測してから詳しくする**（11-25 ユーザー決定）。観測とは、その区画で敵を見た、または撃たれたこと。攻める側の指示で守る側を詳しくすると、「攻められる区画の守りだけが賢くなる」ので避ける。
   - 群が保持の段階に入ったら、3の点数で残すかを決める。群が退いたら外す。
3. **前線の接触**：前線の区画を点数で選ぶ。上限は2区画。
   - 点数（直近10秒）：躍進・走り込みが見られた（1回3点）、弾が当たった（1発1点）、50m以内の射撃（1発0.2点）、兵が倒れた（1人2点）。どれも、実際に起きて誰かが観測した出来事。点数は計算の割り当てにだけ使い、AI の判断材料には渡さない。
   - 5点以上で入る。2点未満が10秒続いたら出る。枠が埋まっていれば、最低の区画の2倍以上の点数で入れ替える。入ってから20秒は追い出さない。（11-25 に見直した。はじめの1.5倍・10秒では、1試合で121〜131回、枠1つにつき約7秒に1回入れ替わっていた。ユーザーの「数値を見直して」）
   - 点数で選ぶ区画でも、守る側は観測してから詳しくする（2と同じ）。

- **時間の上限**：詳しい計算の時間を1フレームごとに測る。平均が仮に1.0msを超えたら、1→2→3の順を守ったまま、3から区画を順に回して処理を減らす。
- 詳しい区画から外れても、兵の動きが急に変わらないよう、決めた配置はそのまま保つ。考え直す間隔だけを長くする。
- 記録すること：
  - 詳しい区画の数の推移（1・2・3の別に）
  - 区画の出入りと入れ替えの回数
  - 詳しい計算の時間
  - 守る側が詳しくなるまでの遅れ（攻撃指示から観測まで）

## 実装の状態（11-25 9時、区画の選び方と記録だけ）

- 試験切替 `-BattleHotSectors=1`（既定0、区画のあるマップだけ）。`BattleHotSectors.cpp` の `UBattleLeaderRuntime::StepHotSectors` が1秒おきに選ぶ。段階1の配置が後で使う問い合わせは `IsHotSector(Team, 位置)`。
- まだ何もこの選び方を読まない。切替を入れても、試合は同じ結果になるはず（確かめる）。
- 点数の入口：
  - 命中（`NoteUnderFire`）：1点。撃たれた軍の「観測」にもなる。
  - 50m以内の射撃（`Fire`）：0.2点
  - 走り込みに気づいた（`StepArmsRush`）：3点
  - 倒れた兵（1秒おきの見回り）：2点
- 観測：1秒おきに、兵が自分で見ている敵（共有された報告ではない）がいるかを調べ、その兵の区画に印を付ける。
- 時間の上限（1.0ms）は、まだ詳しい計算が無いので入れていない。選ぶ処理にかかった時間だけを `hot_select_us` で測る。
- 記録：
  - `hot_enter_*`／`hot_exit_*`／`hot_replace`（区画の出入り）
  - `hot_seconds_player/attack/heat`（区画×秒）
  - `hot_team_seconds`（詳しくする軍×区画×秒）
  - `hot_defender_observed`／`hot_defender_delay_ms`（攻撃指示から守る側の観測までの遅れ）
  - ログ `BATTLE_HOT_SECTORS`（10秒おきの一覧。`x,y:元` に、詳しくする軍 `a`／`b` を付ける）
- プレイヤーの周りでは、プレイヤーの軍は必ず詳しく、相手の軍は観測してから詳しくする（攻撃指示と同じ考え方にそろえた）。

## 段階1aの実装（11-25 10時、試験切替 `-BattleDefendSpread=1`、既定0）

- 差し込んだ場所：区画の任務の小隊が到着場所を割り振るところ（`BuildMovementPlan`、`BattleStableMovement.cpp`）。命令が守り（Defend または Hold）で、遮蔽への到着（マップの遮蔽の候補）があるときだけ使う。
- 中身は `PlanDefendSpread`（`BattleDefendSpread.cpp`）にある。
  - **組**：生き残りが6人未満なら2組、6人以上なら3組。兵は、脅威の向きと直角の向きで、今の位置の左から順に組へ入れる。こうすると、兵どうしの行き先が交差しない。
  - **組の目印**：目的地を通り、脅威の向きと直角な線の上に、12m間隔で置く。
  - **敵が躍進してきそうな遮蔽**：目的地の前方15〜60m、左右40m以内にあって、こちら側に障害物がある遮蔽。こちらの正面からは、そこに来た敵が隠れて見える場所。近い順に24か所まで使う。
  - **見られる数**：候補の遮蔽の目の高さから、そうした遮蔽へ射線が通る数。候補の最初の40か所だけを数える。
  - **兵ごとの候補の順**：「自分の組の目印からの距離 − 見られる数×3m」の小さい順。今までの割り振り（取られた場所、道の長さの確かめ）は、この順で行う。
- 脅威の向きは、その計画の到着の向きを使う。`-BattleArrivalThreat` があれば、区画にいちばん近い知っている敵の向き。なければ、入ってきた向き。
- 遮蔽が少ない場所を補う仕組みは入れていない。
- 記録（切替なしの試合でも、区画の守りの計画ごとに数えるので、比べられる）：
  - `defend_plan_n`、`defend_plan_width_cm`（脅威の向きと直角の向きでの横幅）、`defend_plan_pair_cm`（兵どうしの平均距離）
  - 切替があるときだけ：`defend_spread_plans`、`defend_spread_teams_2/3`、`defend_spread_approach_slots`、`defend_spread_rated`、`defend_spread_view_sum`
- Codex のレビュー（11-25 10時）で3件を直した。
  - 攻める命令で区画を取ったあと守りに移った小隊（攻撃から守りへ）にも、配置を一度だけ入れる（`defend_spread_on_hold`）。
  - プレイヤーが RTS の画面へ戻っても、10秒は自軍を詳しいまま保つ。
  - 躍進してきそうな遮蔽を探す円が、範囲の四隅まで届くようにする。

## 段階1bの実装（11-25 10時10分、同じ切替 `-BattleDefendSpread=1`）

- 区画を守っている小隊（守りの命令で、小隊の中心が区画の中にいる）について、脅威の向きを確かめる。
  - 脅威は、小隊がねらっている敵。いなければ、区画から200m以内でいちばん近い知っている敵。
  - 確かめる間隔は、その軍にとって詳しい区画（`IsHotSector`）なら2秒、それ以外は10秒。
- 脅威が、組を置いたときの向き（`SpreadFacing`）から45°以上ずれたら、その向きに合わせて組を置き直す（`SpreadWant` を `BuildMovementPlan` の向きに使う）。置き直しは10秒に1回まで。
- この小隊では、`-BattleArrivalThreat` の3秒おきの向き直し（`arrival_refacing`）は使わない。二重に動かないようにするため。
- Hold の命令の小隊は、置き直さない（到着場所を作り直さない今の決まりのまま）。
- 記録：`defend_spread_checks_hot/cold`、`defend_spread_replaced_hot/cold`、`defend_spread_turn_waited`（10秒の制限で待った回数）。
- Codex のレビュー（11-25 10時10分）で2件を直した。
  - 置き直すときは、遮蔽の動作中の兵の動作を止める（`ReleaseSpreadCover`、`defend_spread_cover_released`）。止めないと、計画だけ新しい向きになり、兵は古い遮蔽に残っていた。
  - 攻撃から守りへ移ったときの配置で、到着の版は消さない。消すと、着いている兵まで共通の道の先頭へ戻されていた。

## ユーザーの決定（11-25 10時30分、Codex の修正案2つ）

- **目標の手前の区画は、経路から取る。** 群の最初の小隊の移動経路を、終わりから逆にたどる。目標の区画でない最初の区画を、手前の区画にする。経路が無ければ、目標の区画だけにする（`hot_attack_no_path`）。前は、目標から集合地点へ直線で50m戻した位置だったので、マップJ のように山や湖があると、道の上の区画にならないことがあった。
- **詳しい計算の上限は、回数で決める。実時間は記録だけにする。** 実時間で上限をかけると、PC の速さや並列で流す本数で AI の動きが変わり、同じ条件での比較が崩れるため。今の回数の上限：区画は攻撃指示で6、接触で2。配置1回あたり、躍進してきそうな遮蔽は24か所、候補は40か所（視線の判定は最大960回）。確かめる間隔は2秒または10秒。上の「時間の上限（1.0ms）」は取り消す。
- 両軍で共有する6区画の枠は、両軍の群から交互に取る（群の番号の順だと、先に群を作った軍に偏るため）。
- 段階1a・1b は arms に置いて確かめ、main へは契約の修理と移動の詰まりの修正が入ってから入れる。

## 保存する状態と、読み込みで作り直す状態（11-25、割り振りの連絡で決めること）

- どれも保存しない。
- 計算を集める区画（`HotSectors` ほか）：読み込みのあと、1秒で選び直す。点数は直近10秒の出来事なので、読み込み直後は0から数え直す。そのあいだに選ばれる区画は、往復しない試合と違うことがある。今は記録だけなので、試合の結果には影響しない。
- 配置の向き（`SpreadFacing`／`SpreadWant`／`SpreadCheckAt`／`SpreadPlacedAt`）：読み込みのあとは0に戻る。次に到着場所を作るまで、置き直し（段階1b）は起きない。保存の往復で同じ結果にする必要が出たら、`FBattleSquadPlan` の保存に足す（契約の修理の系統と相談する）。

## main へ入れる時機（11-25、割り振りの連絡）

- 段階1a・1b は、兵を実際に動かすために `BattleLeaderRuntime.cpp` と `BattleStableMovement.cpp` を触っている。協議（main `Docs/review-2026-11-25/04-next-implementation.md`）では、契約の修理と移動の詰まりの修正が main に入るまで、ここを広げないことになっている。それまで arms だけに置き、main へは入れない。

## 確かめ方

- 試験切替（既定0）で作り、片側試験（`-BattleArmsTeam` と同じ考え方の、片方の軍だけに効かせる切替）で、切替なしの結果と比べる。比べるもの：得点、与えた損害、撃破、損失、守る小隊の撃った数と隠れていた割合。
- マップH・I・J（区画のあるマップ）で行う。
- 性能は、60FPSの負荷試験で、詳しい計算の時間と1フレームの時間を見る。

## 決まっていないこと

- 数値（組の数、間隔、上限、点数の重み、時間の上限）。
- 実装の順番。案：計算を集める区画の選び方と記録 → 段階1 → 段階2。

## 棚上げ（2026-11-26 20時、ユーザー決定）

- 既定0のまま arms に置く（52ded2e まで）。main へは入れない。
- 結果：
  - 両軍に入れた比較（E1 と I・J × seed 7・43）でも、片軍だけの比較（`-BattleDefendSpreadTeam=0/1`）でも、勝ち負けの向きはそろわない。片軍だけのときは、入れた側が平均で少し損をする。
  - 守る兵の死に方（記録 `defend_*_t0/t1`）には、そろった悪化が無い。守りに付いた延べ時間が ±25% 動くので、損は持ち場の撃ち合いより、だれがどこへ行くかの変化から来ている可能性がある。
- 残っている問題：マップJ s7 で東だけに入れた試合は、同じ凍結ビルドでも毎回結果が違う（400〜420秒で分かれる）。再開するときは、まずこれを直す。
- 詳しい数は main の STATUS（11-26 10時45分・12時10分・20時15分・20時20分）。
