## 2. 作るもの

### 2.1 状態の記録 `-BattleStateTrace=<N>`（既定0）
- 戦闘の開始から N フレームごと（60FPS で N=6 なら0.1秒ごと）に、**状態のかたまりごとの要約の値（ハッシュ）** を1行ずつファイルへ書く（出力先は試合の出力フォルダの `state-trace.csv`）。
- かたまり（それぞれ兵の番号順に並べてから要約する）：
  | かたまり | 中身 |
  |---|---|
  | `pos` | 生きている兵の位置（1cm に丸める）と向き（1度に丸める） |
  | `hp` | 兵の体力・生死・弾薬・盾 |
  | `cover` | 遮蔽の段階・遮蔽の位置・予約・姿勢・制圧 |
  | `sense` | 兵ごとの接触の数と、見えている接触の番号の並び |
  | `plan` | 部隊ごとの命令・目的地・戦術の計画・目標の兵 |
  | `match` | 資源・拠点の持ち主と占領の進み・群・前線・戦略層の局面 |
  | `shot` | そのフレームまでの射撃数と、兵ごとの射撃番号（`ShotSequence`） |
- `-BattleStateTraceDetail=<開始秒>-<終了秒>`：その時間帯だけ、兵ごとの値（要約でなく生の値）も書く。分岐点が分かった後の2回目の実行で使う。
- **記録だけで試合は変わらない**：読むだけで、キャッシュの更新（`AreaIntelView` など）も呼ばない。`-BattleStateTrace` あり／なしの試合が一致することを最初に確かめる。
- 費用：1000人の位置の要約を0.1秒ごとに作る程度（1回あたり数十マイクロ秒の見込み）。記録 ON の試合は時間の比較には使わない。

### 2.2 分岐点を探すスクリプト `Setup/Find-Divergence.py <試合A> <試合B>`
- 2つの `state-trace.csv` を先頭から比べ、**最初に値が違うフレームと、そのかたまり**を出す。かたまりの順（`pos` が先か `sense` が先か）で、原因が移動・認識・判断・射撃のどこにあるかの見当が付く。
- 細部の記録があれば、そのフレームで値が違う兵の番号と項目を出す。あわせて、そのフレームの前後1秒の試合のログ（`BATTLE_*` の行）を両方から抜き出して並べる。

## 3. 使い方（段階2の進め方）

1. `-BattleStateTrace=6` で、死体の消去 0／20 の組を描画なしで1組回す（並列で同時に回せる）。描画なしで分岐が起きなければ、描画ありで1組回す（描画ありは単独で）。
2. 分岐点のフレームとかたまりを出し、その時間帯を `-BattleStateTraceDetail` で回し直して、最初に違った兵と項目を特定する。
3. 死体の消去の操作を1つずつ止める `-BattleCorpseSteps=<mask>`（ブランチ `strategy` に実装済み、既定63＝不変）と組み合わせ、どの操作が効いているかを絞る。
4. `-BattleVATFarLight`、ラグドール（`-BattleRagdoll`）でも同じことをする。
5. 原因が分かったら直す（表示が試合の状態を読み書きしている所を切り離す）。直せない場合（エンジンの都合など）は、その理由と「表示の切替は比較のときに固定する」決まりを MEASURE に書く。
