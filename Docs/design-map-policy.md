## 3. これまでのマップで分かったこと（規則のもと）

1. **区画の中心に物を置くと命令できない**（I v1 の広場10区画の噴水、川の区画の中心が水の中）。
2. **拠点の中央の狭い囲いは詰まる**（I v1：拠点の中心から5m以内で止まった回数93）。v2 で壁を±9m・木箱を±12m に広げた。
3. **2mの隙間は兵が詰まる**（J の事務所ビルの植え込みと車。3m離して合格）。小屋の角（I の G8）も同じ。
4. **本拠地の出口の通り道に丘を置かない**（J：丘の上の面の角に坂が無く、兵が角で止まった）。丘の坂は4辺だけ。
5. **畑が多いと遮蔽の外で撃たれる**（I v1 は畑44% → v2 で25%）。遮蔽の少ない区画は J で植え込み・倒木を足して 6 → 0。
6. **川には底が要る**（H：底が無く隊長が落ち続け、計測が汚れた）。水は「経路網から外す体積＋底」で作る。
7. **同じ規則で比べた遮蔽の使われ方は地図で大きく違う**（11-19、同じ条件：遮蔽地点への到着 H 6.9%・I 22.3%、遮蔽地点の密度 H 106／ha・I 349／ha）。数値監査の値が試合の質の目安になる。
8. **地形を点対称に作っても側の差は残る**。J は既定どうし8本すべてで西が拠点を長く持ち、同点の直し1つで東の4勝に逆転した。原因の深掘りは打ち切り（ユーザー判断 11-22 20時30分）で、試験は「既定との差」で判定する。道が分かれる地図ほど、最初の道の選び方で勝敗が決まりやすい。
9. **回り道がある峠は効かない**（J：本拠地の脇の列が開いていて、峠を避けても4区画を超える遠回りにならず、峠の評価は一度も働かなかった）。
10. **拠点が少なく中央に集まる地図では、集める先を選ぶ意味が小さい**（E：S2 が既定と全く同じ試合になった例）。
11. **手で動かす部下は45cmを超える段差を下りられない**。段差は坂でつなぐか、通れない体積にする。
12. **監査の部隊が途中で全滅すると、その通り道は試されない**（J の F7 は2回目の監査で見つかった）。監査は敵なしの形が要る。
13. **兵が止まる理由は3つに分かれる**（K 版8〜9d、11-25。数え方は `Setup/Analyze-Stalls.py`）。(a) 塀への押し当たり：小隊が塀で分かれ、塀の向こうの兵が共有の経路の最初の点へまっすぐ進む（K 版8 で止まりの35〜39%、拠点の区画の塀の外に集中）。(b) 押しているのに進めない：同じ群の小隊が同じ経路の同じ曲がり角の点（65cm まで近づく決まり）に集まって押し合う（K の街の入口の1点に約150人）。(c) 並んで待っている：前の味方との間隔を保つ決まりで自分から止まる（全体の16〜17%。短ければ問題ではない。ユーザー 11-25）。
14. **出入口の幅より、その奥のすき間の幅が効く**（K）。出入口は6m でも、奥が塀と目隠しにはさまれた4m のすき間だと、そこで直角に曲がる列がつかえる。すき間を6m にすると止まりは 711 → 506（版9、2シードの合計）。
15. **道の脇の出入口は「見通し」と「通りやすさ」が板ばさみになる**（K 版9〜9d）。目隠しを奥へ下げる（6.6m）と、出入口を斜めに抜ける視線が通り、射撃の距離の中央値が 36〜45m → 60m、100m 超が 16〜21% → 35〜39% に延びる。目隠しを長くする（18m）と距離は戻るが、同じ側に立つ2枚がつながって出口が減り、道の上でつかえる（止まり 783、うち約400が入口）。区画どうしの境目（目隠しが1枚ずつ別の側）では、6.6m・18m にしても距離は延びない。
16. **遮蔽の場所は鏡写しに作られない**（K の監査：約2万か所のうち、鏡写しの相手が30cm 以内に無い場所が20%）。「1m 以内に既にあれば作らない」決まりが作る順番に左右されるため。鏡写しの小隊が最初の命令から別の到着位置を取り、西東の動きが最初のフレームから分かれる。`-BattleCoverSlotsMirror=1`（既定0）で東半分を西の写しにすると、開始10秒まで完全に一致する（次のずれは16秒、原因は未調査）。
17. **マップ統計（`Test-MapStats.ps1`）を試合と同時に走らせない**。車両用の足場の生成が終わる前に測り、「届かない」と誤って出た（K 版8）。

## 4. 作成方針

### 4.1 作る前に

- **1マップ＝1つの問い**。新しいマップは「今のマップでは確かめられないこと」を1つ書いてから作る。問いが無いなら、既存のマップに引数で条件を足す。
- **既存のマップは直さない**（A〜J の配置・既定は固定。比較の基準が保たれる）。直したい点は次のマップに入れる。
- **区画図を先に見せる**。区画の表（1区画1文字）と拠点・道・通れない所を SVG にし、ユーザーの了解を得てから実装する（`Setup/Export-MapI.py` の形）。
- 新しいマップは**別の作業フォルダー**で作り、生成・ビルド・試合は計測ロックの番で行う。調査の掲示板に登録する。

### 4.2 共通の型（H・I・J と同じ。変えるときは理由を書く）

- 広さ 1000m×700m、区画 50m（20×14）、東半分の表＋180度回転。本拠地は東西の端。
- 表から生成・規則（拠点・高さ・道・区画の種類）を作る。値は `FMapDef` に置く。配置の名前に版を付ける（例 `sectors-v2`）。
- 入れる建物は1区画に1つまで。拠点は特定の区画（6〜8つ）。
- 小さい地図（6章の案1）のように広さを変えるときも、区画50mと表の形は保つ。

### 4.3 配置の規則（数値は叩き台。生成のときの自己検査で数える）

| 項目 | 規則 | もと（3章） |
|---|---|---|
| 区画の中心 | 経路網の上で、半径3m以内に物を置かない。通れない区画（山・湖・川）は命令を断り、理由を出す | 1 |
| 遮蔽 | 畑以外の区画は、東西どちらから見ても隠れて立てる場所が6つ以上。畑は全体の25%まで、畑だけの行（南北1列）を作らない | 5、前線軍 |
| 隙間 | 物と物のあいだは「閉じる（60cm以下）」か「3m以上」。1〜2.5m の隙間を作らない | 3 |
| 拠点の区画 | 囲いは中心から9m以上離す。出入り口は2方向以上、各3m以上 | 2 |
| 本拠地の出口 | 3方向以上に、幅10m以上で物の無い出口。出口から2区画以内に丘・囲いを置かない | 4、8人×複数部隊 |
| 段差 | 45cmを超える段差は坂でつなぐか、通れない体積にする。2mを超える高さは `-BattleTerrainGoal` が入るまで使わない | 11、高低差の設計 |
| 水 | 経路網から外す体積＋底。橋・浅瀬は幅3m以上（戦車を通す橋は10m） | 6 |
| 道 | 両本拠地をつなぐ戦車の通れる道を1本以上。区画の境目に置く | 車両 |
| 見通し | 数値監査の視線の中央値を問いに合わせて決めて書く（I は73〜148m）。300mを超える直線の通りは、途中に見通しを切る物を置く | 7、SightTeamMask |
| 多様さ | 同じ種類の区画が隣り合うときは、配置の候補か向きを変える（J の「候補×8通りの向き」「境界4種」を使う） | ユーザー要望 |
| 通れない地形 | 全体の15%まで（J は34区画＝12%）。**効かせたい峠・橋には、4区画以内の回り道を作らない** | 9 |
| 拠点の置き方 | 道（領域）ごとに1つ以上。中央の1か所に集めない | 10 |
| 側の差 | 最初の分かれ道が1回の二者択一にならないよう、道どうしを途中でつなぐ（峠・橋を2つ以上） | 8 |
| 塀の出入口 | 高い塀（兵が越えられない）の出入口は幅6m以上。**その奥のすき間（塀と目隠しのあいだ）も6m以上**。目隠しは出入口の両側へ6m以上はみ出す長さ（6.6m 奥なら18m）にし、隣の目隠しとつなげない（あいだを6m以上あける） | 13、14、15 |
| 道の脇の塀 | 道（部隊が列で通る所）に面した出入口は、見通しと通りやすさを両立する形がまだ無い（15）。当面は、遠くを見せたくない地図では4.6m 奥・14m（止まりは増える）、通りやすさを優先する地図では6.6m 奥・14m（射撃の距離が延びる）のどちらかを選んで書く | 15 |
| 塀で囲んだ拠点の区画 | 部隊が塀をはさんで分かれやすいので、各辺に出入口を2つ以上。塀の外から中の中継点へまっすぐ進んで止まる数を合格の手順で数える | 13 |
| 群の経路の集中 | 本拠地から街・拠点へ、並行して使える入口を2つ以上用意する（入口が1つだと、道の分散 `-BattleRouteLoad` も効かない） | 13 |

### 4.4 合格の手順（順に。前が通らなければ次へ進まない）

1. **生成の自己検査**：`URBAN_MAP_RESULT`・`TERRAIN_MAP_RESULT`・区画ごとの遮蔽・通れない所の検査がすべて failures=0。
2. **数値監査**（`Test-MapStats.ps1`）：遮蔽地点の密度、視線の長さ、畑の割合を、I・J の値と並べて記録。
3. **区画の監査**（`-SectorAudit`、敵なし）：全区画への命令の受け付けと、8部隊の到着・保持が failures=0。
4. **既定どうしの試合**：遊ぶ条件（`-CoverActions 1 -FlankCoordination 1`）で、離れたシード2つ×左右入れ替えの4本。完走、詰まりの数（I と同程度か）、遮蔽地点への到着の割合、拠点を持った時間の西東の比を記録する。**側の差は合否にせず記録する**（4本とも同じ側なら「勝ち数で判定しない地図」と表に書く）。
   - 止まりは `Setup/Analyze-Stalls.py` で「塀への押し当たり／押しているのに進めない／並んで待っている」に分け、場所の上位も見る。数えるのは前の2つ。「並んで待っている」は30秒以上続くものだけを問題とする（ユーザー 11-25）。1か所（5m 四方）に全体の1割を超えて集まる場所があれば、その場所の形を直す。
5. **既存マップの不変**：A・E・I の既定の試合が前と一致。
6. **画面の確認**：描画ありの撮影 → ユーザーのテストプレイ（デスクトップにショートカット）。
7. 記録：STATUS、ROADMAP の「マップ」の行、SWITCHES・CODEMAP の作り直し。

所要の目安：区画図まで約1時間（ロック不要）、実装2〜3時間（ロック不要）、生成と手順1〜5で約1時間（ロックの番）。

## 5. 道具として先に用意するとよいもの（どのマップにも効く）

- 生成の自己検査に 4.3 の「区画の中心」「隙間」「本拠地の出口」を足す（今は遮蔽と通れない所だけ）。
- 区画の監査の「敵なし」の形（3章の12）。
- ミニマップと区画の格子に山・湖を描く（J の残り）。

## 6. 次に作るマップの候補（問いごと。文字は作るときに K から順に付ける）

## 7. ユーザーに決めてもらうこと

1. この方針（4章）でよいか。数値（畑25%、隙間3m、遮蔽6つ、通れない地形15%）は委任でよいか。
2. 次に作るマップ：案1（密な市街地）から始めてよいか。広さを小さくしてよいか（1000m×700m をやめるのは初めて）。
3. 側の差：合否にせず記録する扱いでよいか。
4. 5章の道具を先に作るか（約1〜2時間、マップ作りと同じロックの番で確かめられる）。
