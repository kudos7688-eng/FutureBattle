# マップK（密な小さい市街地）の区画図の案

2026-11-22 20時40分 Claude（マップ）。[新しいマップの作成方針](design-map-policy.md) の案1。ユーザーの「案1で進める」による。**区画図の段階**で、実装・生成・計測はしていない。配置と数はユーザーが決める。

区画図：[MapK-Sectors.svg](MapK-Sectors.svg)（`python -I Setup/Export-MapK.py` で作り直せる）

## 1. 問い

近い戦い（30〜50m）を、見通しを切る引数（`-CloseRange 50`）でなく**地形で**起こしたとき、個人AI（撃ち返し・詰め寄り・近接・手りゅう弾・遮蔽の選び方）がどう動くか。

## 2. 形

- 広さ 600m×400m、50m の区画 12×8（96区画）。東半分の表＋180度回転（方針の共通の型と同じ。広さだけ小さい）。
- 東半分（列 G〜L、北の行8 → 南の行1）：
  ```
  行8  A H Q B H G
  行7  Q B O H A U    北の拠点 O（I7）
  行6  H P A Y B H
  行5  B Q H C S S    本拠地 S（K〜L、行4〜5）
  行4  P O A H S S    中央の拠点 O（H4）
  行3  A H Y B Q H
  行2  H K U O H A    南の拠点 O（J2）
  行1  G A W H B G
  ```
  文字はマップJ と同じ部品：H 入れる2階建ての家、B オフィスビル、A 集合住宅、Q 商店、C 教会、K 工場、U 廃墟、W 倉庫、Y 駐車場、G 公園、P 広場、O 拠点（広場と入れる家）、S 本拠地。
- 数（全体）：入れる家 24＋拠点の家 6（96区画のうち30）、ビル 12、集合住宅 14、商店 8、公園 6、広場 4、駐車場 4、廃墟 4、教会・工場・倉庫 各2。**畑・林・丘・水・山は無い。**
- 拠点 6つ：C7・D2・E5（西半分）、H4・I7・J2（東半分）。北・中央・南に2つずつで、中央の1か所に集めない。中央の2つ（E5・H4）は150m離れている。
- 大通り（戦車が通れる、幅10m）：両本拠地をつなぐが、途中で2回折れる（東は y=+50m、中央は y=0、西は y=−50m）。まっすぐ見通せるのは最長200m。
- 通り（幅6m）：150m ずつの短い区間をずらして置く。まっすぐ端から端まで見通せる通りは作らない。
- 本拠地は 100m×100m（I・J は 150m×150m）。

## 3. 方針の規則との照らし合わせ

| 規則 | この案 |
|---|---|
| 入れる建物は1区画に1つまで | 守る（H・O に1軒ずつ） |
| 畑25%まで、畑だけの行を作らない | 畑なし |
| 同じ種類が隣り合わない | 表の上下左右で同じ文字の隣り合いは無い（中央の境目を含む） |
| 300m を超える直線の通りを作らない | 大通り最長200m、通り150m |
| 両本拠地をつなぐ戦車の道 | 大通り1本 |
| 拠点は道ごとに1つ以上 | 北・中央・南に2つずつ |
| 通れない地形 | なし |
| 区画の中心・隙間3m・遮蔽6つ・拠点の囲い9m・本拠地の出口 | 実装のときに生成の自己検査で数える（J の部品の配置を確かめ直す。駐車場・公園・広場は遮蔽が少なくなりやすい） |

## 4. 実装で気を付ける点（区画図の了解の後）

- **広さが初めて変わる**。`FMapDef` の広さ、区画の数（`BattleSectors::Columns/Rows` は 20×14 の定数）、区画の監査の行き先、前線軍の行、ミニマップと区画の格子、本拠地の出現位置（25部隊が 100m 四方に収まるか）を、広さを表から読む形に直す必要がある。既存のマップの試合が変わらないことを確かめる。**ここが一番の手間で、実装2〜3時間の見積もりは 4〜5時間に伸びる見込み。**
- 小さい地図では試合が早く決まる。得点の上限・収入は I と同じで始め、短すぎれば値を調整する。
- 見通しの目安：数値監査の視線の中央値 40〜60m。届かなければ通りに車・植え込み・バリケードを足す。
- 合格の判断は方針の手順どおり。改善かどうかを問う比較は、11-22 の決まり（同じマップ・seed・条件で切替 OFF と ON を比べ、項目ごとの差がプラスのときだけ改善。`MEASURE.md`）に従う。

## 5. ユーザーに決めてもらうこと

1. この区画図でよいか（建物の割合、拠点6つの位置、大通りの折れ方）。
2. 広さを変える手間（4章）を避けるために、**I・J と同じ 1000m×700m の枠のまま中央の 600m×400m だけを街にし、外側を通れない地形（山）で囲む**形も取れる。区画の数が変わらないので実装は約半分で済み、既存のマップに触れない。見た目は「山に囲まれた街」になる。どちらにするか。

## 6. 実装（11-22 20時50分、ブランチ `mapk`・作業ツリー `FutureBattle-mapk`。ユーザー決定「山で囲む形で」）

- 枠はマップI・J と同じ 1000m×700m、区画 20×14。街は列 E〜P（4〜15）・行 4〜11（3〜10）の 600m×400m、96区画。外側は山 `M`（通れない・見通しを遮る、152区画）。
- 本拠地はマップJ と同じ位置（x=±420m、列 R〜T・行 6〜9）。街と本拠地のあいだの1列（列 Q、行 6〜9）は公園・広場・駐車場の空き地。生成コマンドの本拠地まわりの固定値と出現位置に触れないため。両本拠地は 840m 離れる（街の端まで約120m 歩く）。
- 区画の表・道・拠点・入れる家は `BattleMapK.h`。配置はマップJ の `BattleMapLayoutJ.inl` を、名前空間だけ K に差し替えて使う（J のファイルは変えていない。J の地図は作り直さない）。
- 街の中の表は区画図の案のまま。ただし案で本拠地だった4区画は集合住宅・駐車場・公園・ビルにした。
- 道：大通りは 本拠地 → x=350m → y=+50m → x=100m → y=0 → x=−100m → y=−50m → 本拠地。北の通りは両端が y=+150m、中ほどが y=+100m（南はその回転）。まっすぐ見通せる道は最長250m。通り道（中央・北・南・つなぎ）は道の上に置いた。
- 拠点6つ：G10・H5・I8（西）、L7・M10・N5（東）。最初の持ち主なし、値1、収入の倍率0.7（仮）。
- 区画AIの組み合わせの既定（`bSectorCombo`）はマップJ と同じく付けていない（I だけ、ユーザー決定）。試合では引数で入れる。
- 方針の「通れない地形15%まで」は、街を囲む枠の山には当てはめない（街の中に通れない区画は無い）。
- 残り：ミニマップに山を描く処理は無い（J と同じ）。

## 7. 生成と計測の結果（11-22 21時45分。詳しくは STATUS の同じ時刻の項目）

| 版 | 中身 | 街の視線 中央値／90%点 | 射撃の距離 中央値 | 50m以内の射撃 |
|---|---|---|---|---|
| 1 | J の部品のまま＋不足の遮蔽 | 26m／100m | 約140m | 1% |
| 2 | ＋道のトラック（互い違い） | 24m／97m | 約130m | 1% |
| 3 | ＋道の無い境目に高さ2.5m の塀 | 13m／53m | 約100m | 13〜17% |
| 4 | 塀を角から角まで＋3m の出入口2つ | 17m／60m | 約96m | 10〜18% |
| 5 | 出入口を6m に広げ、4m 奥に目隠しの塀14m | 14m／47m | 52〜73m | 28〜47% |
| 6（今の地図） | 道の両脇にも塀・出入口・目隠し。トラックは1台ずつ互い違い | 8m／35m | 47〜52m | 48〜51% |

- 自己検査・区画の監査は不合格0、戦車は拠点すべてに着く、試合12本は完走。
- 建物を密にしただけでは近い戦いにならなかった。AI は交戦距離の端で止まって撃ち、立った兵の目線は低い遮蔽の上を通る。目線より高い塀で区画の境目を切ると縮むが、30〜50m にはまだ届かない。
- 版3は移動の詰まりが増えた（626〜1168。版1は426〜666）。
- 方針（`design-map-policy.md`）への反映の候補：「見通しは立った目線（150cm）で測る。低い遮蔽は見通しを切らない」「近い戦いを狙う地図は、区画の境目を目線より高い物で切る」。
- 版4（11-23 01時52分）：`-BattleShotLog` で調べると、版3の 100m 超の射撃の98%は見えて撃っていて、半分以上が塀の角の空きがつながった区画線沿いの通路か、角を斜めに抜ける線だった。塀を角から角までにすると通路沿いの射撃は約7分の1になったが、遠い射撃は区画の中を通る別の線へ移り、中央値はほぼ変わらない。地形だけでは 100m 前後が下限で、30〜50m には AI の止まる距離を変える必要がある。
- AI の撃ち始める距離（11-23 07時37分）：既存の引数 `-BattleRangeEngage=5000 -BattleRangeEngageSupport=8000` を付けると、版4で中央値 39〜42m・50m 以内 90〜94%。80m/120m では中央値 60m。既定（150m/250m）は 91〜96m。マップK の既定にするかはユーザーの判断待ち。
- 版5（11-23 09時42分、ユーザーの指摘による）：版4の 100m 超の射撃の76〜92%は塀の3m の出入口をまっすぐ通っていた。出入口の奥に目隠しの塀を置くと、交戦距離を変えずに中央値 52〜73m・100m 超 9〜19%。詰まりの約6割は大通りの脇の出入口1か所の混雑で、出入口を6m にすると最大 1160 → 391。方針への反映の候補：「区画の間の通り口は、通れるが見通せない形（目隠し）にする」「通り口は6m 以上」。
- 版6（11-23 10時57分、ユーザーの「道沿いも切る」「戦車が入れない区画があるのは良い」）：道の中心から5m の両脇に塀を置き、区画への出入口は目隠しつき。戦車は道だけを通る。1回目は塀とトラックのあいだが狭く戦車が街に入れなかった（車両の通れる幅は半径2m）。方針への反映の候補：「道を塀で挟むときは車両の幅（4m）＋余裕を残し、試合で戦車が中央まで着くことを確かめる」「車両の到達を生成の自己検査に足す」。
- 版7（11-24 04時42分、ユーザーの「車体の幅と、向かうかどうかの判定の幅を分ける」）：道のトラックを縦向きにして道の端へ寄せた（塀とのあいだ 4.9m → 7.1m）。試遊で戦車が塀の出入口のすき間（4m）に3分以上はまったため。車体の当たりを半径1.5m、車両ナビの半径を2.5m（判定の幅5m）にすると、戦車は街に届き、出入口で押し続けることが0になる（元の値では seed 7 で1両が約5分）。半径3m（幅6m）は街の入口（x=±306〜354m）を通れず0両。既定の値（半径2m・2m）は変えていない。
- 車両が入れる範囲（11-23 17時02分）：定義は車両用のナビメッシュそのもの（幅4m に足りない所は自動で範囲外）。試験切替 `-BattleVehicleRoadGoal=1`（既定0）で、範囲から6m より離れた行き先への車両の指示を断らず、15m・30m・60m 以内の最寄りの範囲内（区画の脇の道）へ向かわせる。AI の試合ではこの場合は起きない（マップK 4試合で0回、切替の有無で結果は一致）。プレイヤーの指示での動きは未確認。
