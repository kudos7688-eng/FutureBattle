# 性能の基準の取り直しと、残る止まり・40部隊・戦車の負荷（ROADMAP「随時」負荷の設計）

2026-11-22 1時15分 Claude（ロードマップに従う改善活動）。**設計（計測の計画）のみ。未計測。** 出どころは ROADMAP 11-20「随時」の負荷（60FPS・マップAの基準、30FPS固定の試合モードで開始時75ms、`-BattleFollowerAnimSkip`、小隊上限40は1フレーム約1.5倍）と `PERFORMANCE.md`。

## 1. 今の問題

| 問題 | 分かっていること |
|---|---|
| 基準が古い | `PERFORMANCE.md` の基準（マップE・30FPS・描画あり、平均11.7ms）は 11-18 の既定。その後、部隊群・対称な開始（11-20）、遮蔽優先・前線軍・死体のラグドールと消去（11-21）、小隊上限30（11-20）が既定になり、区画AIの `-BattleArrivalWalk` も既定になる見込み（11-22）。**今の既定の負荷は誰も測っていない** |
| 60FPS・マップA・マップI の基準が無い | 主の区画マップは I（11-20 ユーザー決定）なのに、I の描画ありの基準が無い |
| 開始時の止まり75ms | 30FPS固定の試合モードでは、開始までの待ち（ゲーム時間10秒）が実時間で約1.9秒しかなく、経路網の作成が終わらない。計測の条件の問題で、プレイでは起きない見込み（未確認） |
| 小隊上限40は約1.5倍 | 11-20 の squadcap の計測。内訳は未集計 |
| 戦車がいると認識が 3.8→9.0ms | 11-17 の記録。車両は通常の兵からも200mで見える（`VehicleSpotRange`）ので、視線判定の組が増えるとみられる |

## 2. 計測の計画（ロックの長い番で、単独・描画ありで回す）

1. **新しい基準**（今の既定がそろってから。区画AIの既定化の後）：マップE と I、60FPS 固定、seed 7、1920×1080 の画面外描画、トレースなし／あり（`-Trace 'cpu,frame'`）を各1本。`Test-WideSight -Area -ObserveTactics -Experiment -Rendered -Fps 60 -CoverActions 1 -FlankCoordination 1`。結果で `PERFORMANCE.md` の表を書き換える（追記しない決まり）。所要は1本あたり約15分（900秒の試合、描画あり）で、4本で約1時間。
2. **同じ試合のぶれ**：同じ条件を2回回して平均の差を見る（11-18 は約0.5ms）。0.5ms より小さい改善は複数本で判断する。
3. **小隊上限40の内訳**：マップI・`-AreaMaxSquads 40`・トレースあり1本。認識・兵の行動・HUD・アニメーションの区間ごとに 30 と比べ、増えた所を対策の候補にする。
4. **戦車あり**：マップI・`-AreaTankKeep 2 -AreaATKeep 2`・トレースあり1本で、認識の増え方を確かめる。

## 3. 対策の候補（計測の後に選ぶ。結果を変えるものは試験切替・既定0）

| 対策 | 対象 | 試合 |
|---|---|---|
| 開始前に経路網の完成を待つ（実時間の上限つき）`-BattleWaitNav=1`。計測のときだけ使う | 開始時の止まり | 開始前なので変わらない見込み（`-BattleStateTrace` で確かめる） |
| 車両への視線判定を、車両どうし・車両と対戦車兵を除いて間引く（遠い車両は0.8秒ごと） | 戦車ありの認識 | 変わる |
| 部隊一覧・アイコンの描画を、見える行・画面内だけにする | HUD | 変わらない |
| `-BattleFollowerAnimSkip`（試合は不変で −0.8ms）の既定化 | アニメーション | 変わらない。**見た目の確認はユーザー待ち**（11-20 決定：画面で確認してから） |

## 4. 目安

開発機（Core i7-14700KF・RTX 5070 Ti）で、マップI・小隊上限30・描画あり・60FPS の平均 16.6ms 以下、p95 20ms 以下、20ms を超える止まりが開始時以外に無いこと。開発機での結果を基準PCへ持ち込まない（既存の決まり）。
