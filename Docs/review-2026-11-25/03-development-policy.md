## 1. 基本の考え方

新しい試験切替を足すより先に、**契約の修理**（購入・命令・保存が約束どおり動くこと）と**評価の決まりの整理**をする。

## 2. Claude と Codex が合意したこと

### 2.1 修理の順番
1. **B03 委任購入が「残す資源」を使い込む**（`BattleArea.cpp:449`。委任の経路だけ購入費を引いていない。予約の実行時にも確認がない）。購入が確定する直前の共通の判定にする。
2. **B06 補給後に区画任務が点命令になる**（`BattleSquadRetreat.cpp:164,188` ほか同じ形の呼び出し）。元の任務＝命令＋目的地＋区画属性をひとつの構造体にし、復帰の関数を1つにする。補給中に新しい命令が来たら古い任務へ戻さない。復帰は一度だけ。命令の裁定を1か所にまとめる作業の最初の一歩でもある。
3. **B01／B02 壁遮蔽（直接操作）の保存**。覗き位置 80cm を保存の検査（100〜450cm）が拒否する。自由位置の遮蔽はロードで通常スロット扱いになる。重大度は中だが、次のテストプレイの前に直す。
4. **B04 保存に入っていない戦闘状態**（主砲の発射通し番号・装填、Arms の躍進／突撃の時計、突撃中の接近）。古いセーブの扱い（足りない項目の既定値）も決める。
5. **B10 ロード後に兵の処理順が変わる**。一律に UnitID 順へ変えるのは別の設計判断なので、保存の修理とは別のコミットにする。「保存の前後で処理順を保つ」を契約にし、順序を保存する方式と決まった順に統一する方式を比べてから決める。

後回し：B07（交互前進 `-BattleBounding`、既定0。直す予定がないなら休止。壊れた状態で出た「効果なし」は削除の根拠にしない）、B08（主砲の命令制約）、B09（`-BattleSectorSight=2` を評価する前に直す）、B05（壁での往復。テストプレイで再現するなら観測の評価より先）。

### 2.2 保存の合格条件
同じ時刻の往復だけでなく、**過去のセーブへの巻き戻し**と**別プロセスでの読み込み**を分けて確かめる（主砲の通し番号は即時の往復では見つからない）。

### 2.3 評価の決まり
- **機能が動くことの確認**と**通常の試合での有用性**を分ける。前者は短い専用の条件で、後者は発動0回の試合も含め、先に決めた試合を全部集計する（発動0回を除くと都合のよい試合だけ残る）。
- 既存のログで対象の存在と発動を数える：`BATTLE_AREA_HIRE`、`BATTLE_COMPOSITION_EXECUTE success=1`、`BATTLE_HIRE_RESERVE op=buy`、`BATTLE_ARMS_ASSAULT/CHARGE/GRENADE/MELEE`、`BATTLE_FRONT_FOCUS2_GROUP`、`BATTLE_FRONT_ORDER_STEP`。
- まず既存の2シードで基準との差（得点・与ダメージ・撃破・戦死）と発動回数を見る。**採用の候補だけ**、先に決めた未使用の2シードで確かめる。全マップ・左右の総当たりは義務にしない。測っていないマップ・側は表に書く。
- 左右別・マップ別の数字を残す（前線統合は東ONが全部プラス、西ONが全部マイナスだった）。
- 引き算の試験は「兵種の強さ」ではなく「その購入・運用込みの損得」と読む。
- 試合の開始時に、実際に効いている切替の一式を記録する（「既定」が実行ファイルの既定か、試遊の条件か、計測の条件かを区別する）。

### 2.4 観測の原則
文として確定する案：「敵についての判断は、取得元・取得時刻・共有範囲がはっきりした観測情報を使う。自軍の状態と公開されたルールの情報は使える。衝突・命中・損害の解決は真値を使えるが、その結果を未観測の敵情報として判断へ戻さない。」
`ObservedArmour`／`ObservedTactics` の既定化は今週はしない（ObservedTactics は保存の往復の一致を保証しないと設計に書いてあり、保存の修理が先）。`-BattleSectorSight=1` は高速化ではなくルールの変更なので、短い固定の場面で「敵の出現から最初の接触までの時間」「隊長がいないとき発見できるか」を見る。

### 2.5 文書の整理
- STATUS の要約と ROADMAP の食い違い（車両の購入・拠点補給などの既定の状態）を直す。
- `design-front-strategy.md` の根拠から旧 S2 の −69.6／−89.6 を外す（相手側の前線軍が切れていた試験。履歴には「無効」の理由を付けて残す）。
- Planner の到着見積り（直線×1.25＋5秒）を区画グラフの距離に替えるのは、直線の道と迂回路で数件、誤差を実測してから。「移動開始→到着」と「購入→到着」を分ける。

### 2.6 操作の確認（次のテストプレイ）
区間指定→攻撃群→補給→FPS 操作→RTS へ戻る、の通し。壁遮蔽中のセーブとロードも入れる。自動の指標（命令から動き出すまでの時間、命令の上書き回数）は、まず B06 の復帰の経路とプレイヤーの命令だけに限って記録する。

## 3. ユーザーの判断が要ること

1. **切替なしで直してよい範囲**。今の決まりは「挙動が変わるものは既定0の試験切替」。案：「正しい動作を勝敗と関係なく決められるもの（明示された契約への違反、保存する値の欠落）は切替なしで直す。複数の正しい動作から1つを選ぶ変更（処理順など）と、戦術・知覚のルールの変更は今までどおり切替で評価する」。
2. **削除の候補**（1件ずつ判断）：`-BattleVATFarLight`、`-BattleSectorNoRoad`、旧 `-BattleStrategy=2/3/4` と `-BattleStrategyPass`、`Setup/Test-WideSight.ps1` の `BattleFollowSightParallel` 引数（本体に受け手がない）、`LeaderAbilityScale`（宣言だけ）。外骨格の6つの切替とブラインドファイアは残す決定があるので対象外。
3. **`-BattleSectorSight=1` を既定のまま続けるか**（隊長だけが遠くを探す。隊長が遮蔽の陰だと隊員に見える敵を見つけない場合がある）。
