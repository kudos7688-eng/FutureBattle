# 設計：小道・経路・遮蔽を先に決めるマップ作り（案、2026-11-25）

ユーザーの提案（11-25）：「区画内に連続した小道や、移動ルートや有効になるであろう遮蔽をあらかじめ設定してマップ作製するルールにする」。この文書はその設計案。採否と段階の順はユーザー判断。調査は Codex（読み取りのみ）、結果の全文は作業時の記録にあり、ここには要点だけ置く。

## 1. いまの作りと、困っていること

いまは「物を置いたあとで、足場と遮蔽の場所を機械的に拾う」作り。マップを作った時点では、兵がどこを通りどこに隠れるかは決まっていない。

| いまの作り | 困っていること（マップK で測った。`Docs/design-map-policy.md` 3章 13〜16） |
|---|---|
| 遮蔽の場所＝物の外周から95cm 離れた点（`UBattleCover::BuildSlots`）。持っている情報は**位置だけ**。向き・高さ・用途は無い | 高さ2.5m の塀の中央（撃てない）、塀と目隠しのあいだ（通り道）、小道の上（通り道）も遮蔽の場所になる |
| 到着位置は「近い順に、前2.5m に壁がある場所」を先頭から取る。壁を見る向きは進んできた向き。撃てるかどうかは見ない | 敵と違う向きの壁を選ぶ。到着には選ばれるのに、遮蔽の動作（顔を出して撃つ）では「撃てない」と断られる場所がある |
| 経路＝小隊の中心からの足場の最短経路。兵はその折れ線を右へ50／140／230cm ずらして使い、曲がり角の点に65cm まで近づく | 塀で分かれた兵が塀に押し当たる（→ `-BattleCutOffRoute`）。同じ群の全員が同じ曲がり角の1点に集まる（→ `-BattleWaypointCrowd`、道の網では `-BattleRouteLoad`） |
| マップK は区画の中の小道（出入口 → 目隠しの脇 → 合流点）を生成時に計算しているが、**土色の帯を描いて低い物をどかすだけ**。ゲームは小道を知らない | 小道があっても部隊はそこを通るとは限らず、小道の上に止まる |

11-25 に既定にした5つの切替は、どれも「起きたあとの手当て」。この設計は、起きにくい形を先に決める。

## 2. 決めること（3つ）

### 2.1 小道の網（区画の中）
- 区画ごとに「出入口 → 小道 → 合流点 → 出入口」の網を、**幅つき**で持つ（節＝出入口・合流点、辺＝小道の1区間と幅）。
- マップK の生成が既に計算している出入口・目隠し・合流点・小道の矩形を、捨てずに残す。
- 生成のとき、区画の四辺すべてが網でつながることを自己検査にする（いまは引けない辺を数えて省くだけ。版9c で 34辺）。
- 同じ辺の2つの出入口の両方に枝を持たせる（いまは片方だけ）。入口を分けるにはこれが要る。

### 2.2 経路（部隊がどこを通るか）
- 区画へ入る部隊は、足場の最短経路ではなく「入る出入口 → 行き先に近い節」までの小道の列を選び、選んだ列を保つ（道の網の `-BattleRouteLoad`・道を保つ決まりの、区画の中の版）。
- 兵ごとの通り道は、小道の幅の中に横に並べる（いまの3段階の右寄せの置き換え）。
- 曲がり角は「点に65cm まで近づく」ではなく「その区間の終わりの線を越えて、次の区間へまっすぐ歩ける」で進む。
- 足場の経路は、今いる場所から出入口まで・網の出口から到着位置まで・網が使えないときの予備、に残す。

### 2.3 遮蔽（どこに隠れて、どこへ撃つか）
- 遮蔽の場所に、位置に加えて次を持たせる：**向き**（守る向き＝敵を想定する側）、**種類**（上から撃てる低い遮蔽／左端・右端から撃てる壁／隠れるだけ）、**撃つ位置**、**区画**、**用途**（通り道なので止まらない、など）。
- 種類と向きは、生成のとき物の寸法と置き方からわかる（高さ1.2〜1.3m の塀と箱は上から、2.5m の塀は端だけ、目隠しのあいだと小道の上は止まらない）。
- 到着位置は、まず「向きが合い、撃てる種類」の場所から選ぶ。隠れるだけの場所は、再装填・退避・予備に残す（消さない。候補が足りなくなるため）。
- 区画の型ごとに「東西南北それぞれの向きに、撃てる遮蔽が何か所以上」を決めて、生成の自己検査で数える（いまの「隠れて立てる場所6つ」の置き換え）。

## 3. 生成からゲームへの渡し方
- 出入口・目隠し・合流点・小道・遮蔽の場所を返す**共通の計算を1つ**にまとめ、生成（物を置く）とゲーム（読む）の両方がそれを使う。家の位置と高さの表が既にこの形（`BattleMapK.h` と `FMapDef`）。
- 同じ計算式を2か所に写す形は取らない（合流点は建物・家・目隠しの補正にも左右され、式だけ写しても同じ結果にならない。いまも出入口の計算が小道側と塀側の2か所にある）。
- マップ（.umap）に配置の版を持たせ、コードの表と合うことを起動時に確かめる。
- 手で編集したマップを正とする場合は別の渡し方（専用の部品）が要る。今回は生成の規則を正とする。

## 4. 守ること
- **既存のマップ（A〜J）は変えない**。新しい情報が無いマップは、いまの作りのまま動く。
- **試験切替で入れる**（既定0）。同じマップ・同じ seed で切替なしと比べる。
- **セーブ**：部隊が選んだ小道の列・今いる区間は、道の網の保持と同じくセーブに入れる。
- **西東の対称**：向き・左右の種類・撃つ位置も180度回して写す（`-BattleCoverSlotsMirror` は位置だけ写している）。
- **他の系統との重なり**：遮蔽の種類（低い遮蔽／リーンできる壁端）は、掲示板 C23（`FutureBattle-coverlean`、壁の遮蔽判定改善）が AI の遮蔽の動作の側から作っている。種類・向き・撃つ位置の定義は C23 と1つにそろえる。こちらはマップが種類を**先に決めて渡す**側、C23 は**その場で地形から判定する**側。

## 5. 段階（小さい順。各段階で測ってから次へ）

| 段階 | 内容 | 触る所 | 測るもの | 心配な点 |
|---|---|---|---|---|
| 1 | 遮蔽の場所に種類・向き・用途を持たせ、到着位置の選び方に使う（高い塀の中央・目隠しのあいだ・小道の上を、撃つための到着から外す）。まずはゲーム側で物の寸法から判定（マップは作り直さない） | `BattleCover.h/.cpp`、`BattleStableMovement.cpp` | 到着した兵のうち撃てた割合、遮蔽の動作で「撃てない」と断られた数、止まり | 候補が足りず、開けた場所や経路の終点に集まる。C23 と定義を合わせる |
| 2 | マップK の出入口・目隠し・合流点・小道の計算を共通の形に出し、`FMapDef` から読めるようにする（見た目は変えない） | `BattleMapLayoutJ.inl`、`BattleMapK.h`、`BattleFieldLayout.h` | 作り直したマップが前と同じ配置になること | 2回生成・回転・家の例外・拠点の遮蔽の移し漏れ |
| 3 | 区画へ入る部隊が小道の列を選んで保つ。入口ごとに分ける | `BattleLeaderRuntime.cpp/.h`、`BattleStableMovement.cpp`、セーブ | 塀への押し当たり、押し合い、入口ごとの人数 | いまは各辺1枝。`-BattleCutOffRoute` が小道の選択を飛ばさないようにする |
| 4 | 小道の幅に横に並べ、曲がり角を線で越える | `BattleStableMovement.cpp` | 曲がり角の5m 四方に集まる止まり | 合流点・曲がり角・すれ違いで通り道が交わる |
| 5 | マップ作りの決まりに入れる：区画の型ごとに小道の網と向きつきの遮蔽を定義し、自己検査で数える（`design-map-policy.md` 4.3） | 方針書、生成の自己検査 | 新しいマップが検査を通ること | 既存の型（オフィス・集合住宅・教会など）への当てはめの手間 |

## 6. ユーザーに決めてほしい点
1. 段階1から順に進めてよいか（段階1はマップを作り直さず、全マップに効く）。
2. 「有効な遮蔽」は撃てる場所だけを指すか、再装填・退避のために隠れるだけの場所も正式に残すか（案は「残す」）。
3. 入口の分け方はどこまで求めるか：別の辺から入る／同じ辺の2つの出入口を使い分ける／同じ出入口を横に広く通る。
4. セーブとロードを挟んだ試合の一致を、この新しい機能の範囲に限るか（いまも経路・到着位置・姿勢はロードで作り直していて、完全には一致しない）。
