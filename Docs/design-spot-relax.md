# スポットの緩和（敵の位置の知らせ方を緩めて、両軍の攻撃を活発にする）

2026-11-27 作成（系統「スポットの緩和」、ブランチ `spotrelax`、作業ツリー `FutureBattle-spotrelax`）。
実装の進み具合と測定の結果は `STATUS.md`、切替の一覧は `Docs/experiments.md`。この文書は決まりと作りを書く。

## 1. ユーザーの決定（2026-11-27 2時ごろ、原文）

相談（原文）：「敵味方ともにより活発に相手を攻撃するように動かしたい。敵の真の位置をスポットする制御をもう少し緩めてよい。それ以外の方策も考えて」

系統「ミッション」が並べた方法（A スポットを緩める 1〜5、B AI の意思、C 動機、D 攻めに出た小隊が着かない原因）に対する決定（原文）：

> 「1から4まで実装して問題ありません。5について、敵の本当の位置を、分かることが問題なのは、敵の重点がどこにあるかそして本拠地攻撃にどこで、集結してどのようなルートで来るかも分からないようにしたいためです。これについては、条件付きにしたいです。テストでは自由にお願いします。」
>
> 「この点について、他のセッションで行う方が良ければ、そちらの方で行ってください。」

読み方：

- A-1〜A-4 は試験切替（既定0）として実装してよい。既定にするかは、結果を見てユーザーが決める。
- A-5（敵の本当の位置）は、**敵の重点・本拠地攻撃の集結地・進路が相手に漏れない条件つき**でだけ採用の候補にできる。条件の案はこの系統が作ってユーザーに諮る（6章）。
- 試験・診断では A-5 を自由に使ってよい。
- B（AI の意思）・C（動機：得点・報酬）・D（着かない原因）は「考えて」の段階。**実装の許可は出ていない**。案とおすすめを出す（7章）。得点の規則は 11-22 のユーザー決定で「今のまま」。

## 2. 記録にある「攻撃が活発でない理由」

1. マップK で敵が見えない時間が約96%、小隊が敵を知っている時間は約15%（STATUS 11-25 16時00分）。
2. 守る兵の死はほぼ全部が40m以上から、撃った敵が本人に見えていないことが6〜7割（STATUS 11-26 20時15分）。
3. 攻めに出した部隊が着かない：基地の偵察は前線の手前で9回下がる、精鋭は400秒で本拠地に着かない（11-26 12時50分）、補給車狩りは8割が近づけない（11-26 20時10分・21時10分）。
4. 得点は「残した資源＋生存者＋終了時の拠点」で、戦って買い直すほど下がる（`Docs/design-score-economy.md`）。
5. 普通の小銃小隊の躍進・突撃は既定で止めてある（`-BattleArmsAssault` 既定1、11-25 ユーザー決定）。

すでに分かっていること（測り直さない）：

- `-BattleSeekKnown=1|2`（既定0、main）：軍の兵が**自分の目で見た**敵歩兵の位置を50mマスで30秒覚え、手すきの小銃小隊が200m以内のマスへ攻撃移動する。マップK seed 7・43 で与えた損害の合計 +40〜94%（11-25 19時10分）。未使用のシード 239・277 では片方しか増えず、4試合とも勝ちが西から東へ変わったので止めた（11-25 20時05分）。**情報を「向かう」に変える読み手はこれが既にある**。
- `-BattleSpotTrack=5`（既定0）：見失ってから5秒は敵のいまの位置を覚える（向き・遮蔽・目撃マスだけが読む）。
- `-BattleKnownTargetFire=1|2`（既定0、系統「壁の遮蔽判定」）：軍で共有する既知の敵を本人が確かめて撃つ・撃てる位置へ移る。
- `-BattleSquadKnowledge`（11-26 18時から既定1）：分隊の中は遅れなし、分隊どうしは報告。
- `-BattleArriveWatch`（着いたら見張る）は接触が減った（11-25 16時00分）。

## 3. 守ること

- **すべて既定0の試験切替。切替0で試合は1ビットも変わらない**（同じ凍結ビルドの切替なしが台帳の基準と `IDENTICAL`）。切替0のとき、新しい表への書き込み・乱数の消費・処理順の変化をしない。
- **AI の判断は「受け取った情報」だけを読む**。この系統が足す情報は、どれも1つの表（4章の「知らせの表」）に「いつ・どこ・どの程度の確かさ・何で知ったか」を付けて入れ、判断はその表を読む。切替の無い所で敵の本当の位置を判断に入れない。A-5 も、表に入れる入口が1つあるだけにする。
- **撃つ判断は変えない**。射撃には今までどおり本人の視認（または既にある切替の条件）が要る。この系統の情報は「どこへ向かうか・どこを警戒するか」にだけ使う。
- 「ミッション」系統の報酬（敵の作戦＝重点・区間の役割・到着待ちの購入・群の行き先の写し、`Docs/design-missions.md`）とは別の仕組みにする。**この系統が扱うのは敵の兵の位置だけ**で、敵の作戦（重点・役割・群の行き先・購入の予約）は表に入れない。
- 一戦中のセーブは無いので、保存の対応は要らない。

## 4. 作り（2026-11-27 3時、診断の結果で確定）

### 4.0 診断で分かったこと（STATUS 11-27 3時00分）

敵の位置の情報の入口は1本ではない（個人・分隊の接触／軍の見え方 `AreaIntelView`／経路用の一覧／拠点ごとの前線／`-BattleSeekKnown` の目撃マス／`-BattleKnownTargetFire` の表）。診断用の `-BattleSpotTruth` で、マップK 種7：

- 真の位置を軍の見え方に入れるだけでは小銃小隊の損害は増えない（増えるのは重火器の分）。前線は「知っている敵が2人以上いる区画の手前」に線を引くので、知るほど前へは出ない。
- 目撃マスに入れ、向かえる範囲を広げる（`-BattleSeekKnownRange=60000 -BattleSeekKnownMax=8`）と、与えた損害 +85%・撃破 +70%（情報なしで広げるだけなら +28%）。

だから **A-1〜A-4 の知らせは、すべて `-BattleSeekKnown` の目撃マスに入れる**。軍の見え方・個人の接触・射撃には入れない（区画の中心が砲の目標になる、架空の密集目標ができる、を避ける）。

### 4.1 目撃マス（知らせの表）

軍ごとの50mマス → 知らせ1件（位置、知った時刻、種類）。種類：0 本人の目撃（今の動作）、1 伝聞・記憶・偵察（A-1）、2 発砲（A-2）、3 取られた拠点（A-3）、4 司令部（A-4）、5 真の位置（A-5、診断）。同じマスは新しい方が勝つ。粗い知らせ（3・4）は10秒以内の目撃を上書きしない。忘れるのは `-BattleSeekKnownSeconds`（既定30秒）。

読み手は今ある「向かう」だけ：任務中で敵のいない健康な AI の小銃小隊が、`-BattleSeekKnownRange` 以内のいちばん近いマスへ攻撃移動する（1マス `-BattleSeekKnownMax` 小隊まで、着いて10秒何もなければ任務へ戻る）。撃つのは、着いてから本人が見た敵だけ。

### 4.2 切替（すべて既定0。`-BattleSeekKnown>0` のときだけ意味がある）

| 切替 | 内容 | 引数 |
|---|---|---|
| A-1 `-BattleSpotShare=bits` | 目撃マスに入れる接触を広げる。1：今は見えていない記憶と伝聞・分隊の表、2：偵察の遠見と偵察の報告、4：車両 | 記憶の長さは既にある `-BattleSeekKnownSeconds`・`-BattleMemorySeconds` |
| A-2 `-BattleSpotShots=1` | 歩兵の小火器の発砲で、相手の軍の目撃マスに知らせが入る | `-BattleSpotShotsHear=cm`（既定15000：この距離に相手の兵が居れば聞こえる）、`-BattleSpotShotsError=cm`（既定2500：位置の誤差の半径）、`-BattleSpotShotsEvery=s`（既定2：同じ射手の最小の間隔）。誤差は試合の乱数列を使わない |
| A-3 `-BattleSpotLost=1` | 拠点の持ち主が変わったら、相手の軍の目撃マスにその拠点が入る | `-BattleSpotLostSeconds=s`（既定60） |
| A-4 `-BattleSpotHQ=s` | s 秒ごとに、相手の歩兵が居る区画（50m）の中心を、遅れて目撃マスに入れる | `-BattleSpotHQDelay=s`（既定30）、`-BattleSpotHQMin=n`（既定2人以上の区画だけ）、`-BattleSpotHQDepth=n`（既定0＝制限なし。相手の本拠地に近い奥の区画は配らない） |
| A-5 `-BattleSpotTruth=bits`（診断専用） | 1：敵の歩兵の本当の位置を目撃マスへ、2：敵の全員を軍の見え方へ | `-BattleSpotTruthDepth=n`（条件つきの形の試験用。奥の区画の敵は入れない） |

## 5. 進め方

1. **診断（上限）**：済み（4.0。与えた損害で基準の約1.85倍）。
2. A-1〜A-4 を弱い順に：固定場面の試験 → 1試合で発動の確認 → 2シード（`Board.py plan` で申請）で上限にどこまで近づくか。読み手は `-BattleSeekKnown=2`、範囲は既定（200m・2小隊）と広く（600m・8小隊）の2通り。基準は台帳。結果は得点だけでなく両軍の与えた損害・撃破・戦死を並べる。
3. B・C・D は結果を踏まえて案とおすすめをまとめ、ユーザーに諮る（7章）。

## 6. A-5（敵の本当の位置）を採用の候補にするための条件の案

守りたいもの（ユーザー決定）：敵の重点がどこか／本拠地攻撃がどこに集結し、どの進路で来るか、が相手に分からないこと。

| 案 | 見せる敵 | 重点・集結地・進路は漏れるか | 作り |
|---|---|---|---|
| 1 前線の近くだけ | 受け取る側から見て、相手の本拠地の手前 n 列（例：6列＝300m）より手前に居る敵だけ。奥（相手の後方）の敵は見えない | 集結地（後方）は漏れない。進路は、相手が奥から出てきた時点で分かる（来る方向は分かるが、集まっている段階では分からない）。重点は、前線に出ている人数の偏りとして見える | `-BattleSpotTruthDepth=n`（試験用に実装）。区画の列で切るだけ |
| 2 撃ち合っている敵だけ | 直前の数秒に撃った敵・撃たれた敵だけ。歩いているだけ・集まっているだけの敵は見えない | 集結地・進路は漏れない（撃つまで見えない）。重点は、撃ち合いが始まった所として分かる（＝もう隠す意味のない段階） | A-2（発砲の知らせ）の誤差0・遅れ0の形とほぼ同じ。新しい仕組みは要らない |
| 3 区画の単位・遅れ・攻撃の群を除く | A-4 の形（区画の中心、30秒おくれ、人数は出さず「居る」だけ）で、相手の攻撃群・本拠地攻撃の枠・奇襲の小隊は数えない。相手の本拠地の近くの区画も配らない | 攻めに出た群は最後まで見えない。守っている敵の居場所だけが分かる。重点は人数を出さないので読みにくい | A-4 に「数えない小隊」の条件を足す（未実装） |

おすすめ：**案2 を基本にし、足りなければ案3**。案2 は「撃てば位置が知られる」という説明のつく決まりで、集結と進路を何も漏らさない。案1 は作りは簡単だが、前線の人数の偏り（＝重点）がそのまま見える。どれにするか・組み合わせるかはユーザーの判断（測定の結果を添えて諮る）。

## 7. B・C・D の案とおすすめ（実装の許可は出ていない。諮るための材料）

### B AI の意思

診断で分かったこと：情報があっても、動くのは「向かう」（`-BattleSeekKnown`）を入れたときだけ。前線は敵を知るほど手前に線を引く。

| 案 | 内容 | 見込み・心配 |
|---|---|---|
| B-1 「向かう」を採用の候補に戻す（おすすめ） | `-BattleSeekKnown=2` と範囲を、A-1〜A-4 のどれかと組にして 239・277 で確かめる | 11-25 は 239・277 で片方しか増えず、勝ちが東へ片寄って止めた。片寄りの原因（同点のときのマスの選び方・小隊の評価の順）を先に調べる必要がある |
| B-2 接触が無ければ前線を1行進める | 一定時間（例60秒）どの区間にも接触が無ければ、前線の線を1列前へ | 前線の決まり（`-BattleFrontHold`）の変更。系統「戦略層」と調整が要る |
| B-3 敵が少ない区画の手前では止まらない | 「知っている敵が2人以上の区画の手前に線を引く」を、自軍の人数が上回るときは引かない | 同上。情報を増やす切替（A-1〜A-4）を軍の見え方へもつなぐ前提になる |
| B-4 向かう小隊の種類を広げる | 今は健康な小銃小隊だけ。重火器・対戦車班や、攻撃群の小隊も | 持ち場を空ける心配（今も残す小隊数の下限が無い） |
| B-5 敵の位置が分かっているときだけ普通の小隊の躍進を戻す | `-BattleArmsAssault` は 11-25 のユーザー決定で既定1（止めてある） | 決定の変更になるので、数字を添えて諮る |

### C 動機（得点・報酬）

診断の8本で、両軍の得点の合計は基準 1197 → 戦うほど 724〜1092 に下がった（残した資源が減る）。得点の規則は 11-22 のユーザー決定で「今のまま」。変えるなら改めて諮る：戦果点（撃破・与えた損害に点）、拠点の収入差を大きくする、ミッションの報酬（系統「ミッション」が `-BattleMissions` で実装中）。おすすめ：**この系統では得点を変えず、「戦うほど両軍の得点が下がる」数字をユーザーに見せて、戦果点を足すかどうかだけ諮る**。AI は得点を見て戦い方を決めていないので、AI の活発さには得点の規則は直接は効かない（効くのは、どちらが勝つかの評価）。

### D 攻めに出た小隊が着かない

系統「移動の詰まり」（基地の偵察・精鋭の本拠地攻撃）、「群制御」（本拠地攻撃隊）、「弾薬と補給」（補給車の狩り）がそれぞれ原因を追っている。この系統で見えるのは「向かった小隊の2〜3割が敵に会えない／時間切れ」だけ。おすすめ：**重ねて調べず、各系統の結果を待つ**。向かう途中で手前の敵に止められるのは、攻撃としては働いている。
