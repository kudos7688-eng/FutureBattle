# スポットの緩和（敵の位置の知らせ方を緩めて、両軍の攻撃を活発にする）

2026-11-27 作成（系統「スポットの緩和」、ブランチ `spotrelax`、作業ツリー `FutureBattle-spotrelax`）。
実装の進み具合と測定の結果は `STATUS.md`、切替の一覧は `Docs/experiments.md`。この文書は決まりと作りを書く。

## 1. ユーザーの決定（2026-11-27 2時ごろ、原文）

相談（原文）：「敵味方ともにより活発に相手を攻撃するように動かしたい。敵の真の位置をスポットする制御をもう少し緩めてよい。それ以外の方策も考えて」

系統「ミッション」が並べた方法（A スポットを緩める 1〜5、B AI の意思、C 動機、D 攻めに出た小隊が着かない原因）に対する決定（原文）：

> 「1から4まで実装して問題ありません。5について、敵の本当の位置を、分かることが問題なのは、敵の重点がどこにあるかそして本拠地攻撃にどこで、集結してどのようなルートで来るかも分からないようにしたいためです。これについては、条件付きにしたいです。テストでは自由にお願いします。」
>
> 「この点について、他のセッションで行う方が良ければ、そちらの方で行ってください。」

読み方：

- A-1〜A-4 は試験切替（既定0）として実装してよい。既定にするかは、結果を見てユーザーが決める。
- A-5（敵の本当の位置）は、**敵の重点・本拠地攻撃の集結地・進路が相手に漏れない条件つき**でだけ採用の候補にできる。条件の案はこの系統が作ってユーザーに諮る（6章）。
- 試験・診断では A-5 を自由に使ってよい。
- B（AI の意思）・C（動機：得点・報酬）・D（着かない原因）は「考えて」の段階。**実装の許可は出ていない**。案とおすすめを出す（7章）。得点の規則は 11-22 のユーザー決定で「今のまま」。

## 2. 記録にある「攻撃が活発でない理由」

1. マップK で敵が見えない時間が約96%、小隊が敵を知っている時間は約15%（STATUS 11-25 16時00分）。
2. 守る兵の死はほぼ全部が40m以上から、撃った敵が本人に見えていないことが6〜7割（STATUS 11-26 20時15分）。
3. 攻めに出した部隊が着かない：基地の偵察は前線の手前で9回下がる、精鋭は400秒で本拠地に着かない（11-26 12時50分）、補給車狩りは8割が近づけない（11-26 20時10分・21時10分）。
4. 得点は「残した資源＋生存者＋終了時の拠点」で、戦って買い直すほど下がる（`Docs/design-score-economy.md`）。
5. 普通の小銃小隊の躍進・突撃は既定で止めてある（`-BattleArmsAssault` 既定1、11-25 ユーザー決定）。

すでに分かっていること（測り直さない）：

- `-BattleSeekKnown=1|2`（既定0、main）：軍の兵が**自分の目で見た**敵歩兵の位置を50mマスで30秒覚え、手すきの小銃小隊が200m以内のマスへ攻撃移動する。マップK seed 7・43 で与えた損害の合計 +40〜94%（11-25 19時10分）。未使用のシード 239・277 では片方しか増えず、4試合とも勝ちが西から東へ変わったので止めた（11-25 20時05分）。**情報を「向かう」に変える読み手はこれが既にある**。
- `-BattleSpotTrack=5`（既定0）：見失ってから5秒は敵のいまの位置を覚える（向き・遮蔽・目撃マスだけが読む）。
- `-BattleKnownTargetFire=1|2`（既定0、系統「壁の遮蔽判定」）：軍で共有する既知の敵を本人が確かめて撃つ・撃てる位置へ移る。
- `-BattleSquadKnowledge`（11-26 18時から既定1）：分隊の中は遅れなし、分隊どうしは報告。
- `-BattleArriveWatch`（着いたら見張る）は接触が減った（11-25 16時00分）。

## 3. 守ること

- **すべて既定0の試験切替。切替0で試合は1ビットも変わらない**（同じ凍結ビルドの切替なしが台帳の基準と `IDENTICAL`）。切替0のとき、新しい表への書き込み・乱数の消費・処理順の変化をしない。
- **AI の判断は「受け取った情報」だけを読む**。この系統が足す情報は、どれも1つの表（4章の「知らせの表」）に「いつ・どこ・どの程度の確かさ・何で知ったか」を付けて入れ、判断はその表を読む。切替の無い所で敵の本当の位置を判断に入れない。A-5 も、表に入れる入口が1つあるだけにする。
- **撃つ判断は変えない**。射撃には今までどおり本人の視認（または既にある切替の条件）が要る。この系統の情報は「どこへ向かうか・どこを警戒するか」にだけ使う。
- 「ミッション」系統の報酬（敵の作戦＝重点・区間の役割・到着待ちの購入・群の行き先の写し、`Docs/design-missions.md`）とは別の仕組みにする。**この系統が扱うのは敵の兵の位置だけ**で、敵の作戦（重点・役割・群の行き先・購入の予約）は表に入れない。
- 一戦中のセーブは無いので、保存の対応は要らない。

## 4. 作り（案。Codex の調査で入口を確かめてから確定する）

### 4.1 知らせの表

軍ごとに1つ。行は「知らせ」1件：

| 項目 | 内容 |
|---|---|
| 種類 | 発砲（A-2）／区画の持ち主（A-3）／司令部（A-4）／真の位置（A-5、診断） |
| 位置 | 点（発砲・真の位置。発砲は誤差つき）または区画の中心（A-3・A-4） |
| 広がり | 誤差の半径（点）または区画ID |
| 数 | 概数（A-4 は区画の人数を丸める。A-3 は「居る」だけ） |
| 時刻・期限 | 知った試合時刻と、忘れる時刻 |
| 敵のID | 発砲と真の位置だけ（同じ兵の知らせを上書きするため）。区画の知らせには無い |

読み手（どれも既にある切替の中で、表の行を「軍が見た敵」と同じ扱いで足す）：

1. `-BattleSeekKnown` の目撃マス（手すきの小銃小隊が向かう）。
2. `AreaIntelView`（前線・重点・群・側面路などが読む軍の見え方）。位置が区画のものは、読み手ごとに入れてよいかを分ける（砲撃の目標・射撃には入れない）。
3. 作戦画面の表示（プレイヤー側の軍だけ。古い情報の印）。

### 4.2 A-1 記憶と共有

今の決まり（接触の寿命、16m・0.8秒の報告、分隊の表、分隊間の報告）を調べ、足りない所だけを引数にする：

- 軍の目撃マスの記憶 `-BattleSeekKnownSeconds`（既定30、5〜180）は既にある。
- 目撃マスへ入れる目撃の種類を広げる（今は本人の目で見た歩兵だけ。伝聞・偵察の遠見・車両を入れる切替）。
- 向かえる距離 `-BattleSeekKnownRange`（既定200m）・1マスの小隊数 `-BattleSeekKnownMax`（既定2）は既にある。

### 4.3 A-2 小銃の発砲で位置が知られる

`FFireReveal`（砲・戦車砲）と同じ形で、歩兵の発砲を相手の軍の表に入れる。引数は、聞こえる距離（発砲点から相手の兵までの距離）、誤差の半径、記憶の秒数。誤差は試合の乱数列を使わず、兵のIDと時刻から決める（切替0で乱数の消費が変わらないように、また並列でも同じになるように）。

### 4.4 A-3 取られた拠点・区画

拠点・区画の持ち主が敵に変わったら、その区画に「敵が居る」の知らせを入れる（位置は区画の中心、期限つき）。

### 4.5 A-4 司令部の情報

決まった間隔（例60秒）で、敵の兵の位置を区画ごとに数え、遅れ（例30秒）を付けて両軍の表に入れる。数は概数。敵の作戦は入れない。

### 4.6 A-5 真の位置（診断用）

決まった間隔（1秒）で、生きている敵の全員の位置を表に入れる。試験と診断にだけ使う。条件つきの形は6章。

## 5. 進め方

1. **診断（上限）**：A-5 を入れ、マップK seed 7 の1試合（`-CoverActions 1 -FlankCoordination 1`、30FPS、凍結ビルド）で、接触・発砲・与えた損害・前進・拠点の取り合いがどれだけ増えるかを見る。読み手が既定で切れている（`-BattleSeekKnown` 既定0）ので、(i) A-5 だけ、(ii) A-5＋`-BattleSeekKnown=2` の2本を、(iii) 台帳の基準と (iv) `-BattleSeekKnown=2` だけ、に並べる。増えなければ原因は AI の意思か到達にあるので、その結果を持ってユーザーに方針を尋ねる。
2. 増えたら A-1〜A-4 を弱い順に：固定場面の試験 → 1試合で発動の確認 → 2シード（`Board.py plan` で申請）で上限にどこまで近づくか。基準は台帳。結果は得点だけでなく両軍の与えた損害・撃破・戦死を並べる。
3. B・C・D は結果を踏まえて案とおすすめをまとめ、ユーザーに諮る。
